# 日本語活用表 作業ミス防止メモ

## 背景

`日本語助動詞一覧.xlsx` に助動詞の活用表と用言の活用対応表を同居させて作業した際、保護すべき `Sheet1` の助動詞活用表に、用言活用対応表の内容が混ざる事故が起きた。

その後、`用言活用対応表` を `日本語用言活用対応表.xlsx` として分離した。今後は、助動詞表と用言表を別ファイルとして扱う。

## 起きた問題

- `Sheet1` は触らないという条件があったが、作業途中で助動詞表に用言表の内容が混ざった。
- 最新の Git 版を復元元にしたところ、その版の `Sheet1` 自体がすでに壊れており、復元したつもりでも直っていなかった。
- PDF出力やページ数確認は実施したが、印刷ページ上での改行・折り返しの見え方確認が不十分だった。
- `用言活用対応表` の左側メモ、文語・口語の対応メモ行、活用形ラベルなど、印刷時に見え方が変わる箇所の確認が後追いになった。

## 原因

- 同一ブック内に、保護対象の助動詞表と新規作成中の用言表を置いたため、シート取り違えやシートXML取り違えのリスクが高かった。
- 「Gitの最新状態なら正常」と仮定して復元したため、壊れる前の正常コミットまで遡る確認が遅れた。
- Excelの画面上の表示、セル値、PDF印刷結果を別物として扱う意識が足りなかった。
- ページ数だけを確認し、印刷PDF上で文字が折れていないか、メモ行が十分か、罫線が意図どおりかの視覚確認が不足した。

## 今後の原則

1. 助動詞表と用言表は別ファイルで管理する。
   - 助動詞: `日本語助動詞一覧.xlsx`
   - 用言: `日本語用言活用対応表.xlsx`

2. 「触らない」と指定されたシートは、作業対象から物理的に分離する。
   - 可能なら別ファイル化してから作業する。
   - 同一ブック内で作業する場合は、シート名と内部XMLの対応を必ず確認する。

3. 復元時は最新コミットを信用しすぎない。
   - 最新版に問題が残っている可能性を考える。
   - 複数コミットを確認し、正常な内容が検索で確認できる版から復元する。

4. Excel作業では、確認を三段階に分ける。
   - セル値の確認
   - 印刷設定の確認
   - PDF画像化による見た目確認

## 印刷確認チェックリスト

Excelファイルを保存する前後に、次を確認する。

- A4縦1ページに収まっているか。
- 印刷倍率が意図した値になっているか。
- 印刷範囲が必要な列・行を含んでいるか。
- 文語・口語の対応メモが印刷時に不自然に改行されていないか。
- `未然形` `連用形` `終止形` `連体形` `已然形` `仮定形` `命令形` が印刷時に改行されていないか。
- 表全体の外枠、文語と口語の境界線、主要区切り線がそろっているか。
- 左側に置いた補足メモが印刷範囲に含まれているか。
- 補足メモのフォントとサイズが表内文字と合っているか。

## 用言活用対応表での列幅ルール

助動詞表で使った考え方を、用言表でも使う。

- セル内の最大行数が1行の列は、狭めの列幅にする。
- 最大2行の列は、中間の列幅にする。
- 最大3行の列は、広めの列幅にする。
- ただし、左側補足メモ列は本文列とは別扱いにし、読みやすさを優先する。

## 作業時の注意

- `Sheet1` という名前だけで判断しない。内部では `sheet1.xml` とは限らない。
- 作業前に `workbook.xml` と `workbook.xml.rels` の対応、または Excel COM でシート名を確認する。
- 復元時は、対象シートに混入語が残っていないか検索する。
  - 助動詞表なら、`用言` `見る` `堂々` `上一段` `四段` などが出ないことを確認する。
  - 用言表なら、必要な補足語が残っていることを確認する。
- PDF化後の画像を見て、ページ数だけでは分からない崩れを確認する。
