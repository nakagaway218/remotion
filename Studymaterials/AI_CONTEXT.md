## 英作文教材の派生作成

`中学生英作文一般動詞現在形編.xlsx` は、`中学生英作文be動詞現在形編.xlsx` から派生させた。

基本例文は `私はテニスをします。`。主語別に、肯定文、否定文、疑問文、Yes/No の返答を練習する。三単現の主語では `plays`、否定文では `does not / doesn't`、疑問文では `Does ... play ...?` を使う。

派生時に起きた注意点:

- 行数が変わるため、元ブックの改頁位置をそのまま使わない。
- Excel の手動改頁は「指定行の後で改頁」なので、次ページの見出し行の1行前に入れる。
- 一般動詞現在形編では、改頁位置は `32, 62, 92, 122`。
- 元ブックの太い横罫線が古いブロック位置に残ることがある。タイトル行と実際の主語見出し行だけに置き直す。
- 一般動詞現在形編の太い横罫線は `1, 3, 18, 33, 48, 63, 78, 93, 108, 123`。
- 内容がページ上部に寄る場合は、上下余白をそろえ、垂直中央寄せを有効にする。
- 注釈行のフォントは全ブロックで統一する。一般動詞現在形編では `4, 19, 34, 49, 64, 79, 94, 109, 124` を斜体にした。
- `私` / `私たち` の疑問文は、実際の会話では相手が `you` で答えるのが自然になる。解答では `I` / `we` のままにせず、`you` に直す。該当ブロックには、相手が答える形なので返答では `I / we` ではなく `you` を使う、という注釈を入れる。
- 注釈が長くなる場合は、既存注釈を消さずに2行化する。行高を広げ、折り返しと垂直中央寄せを確認する。今回の該当注釈行は行高 `36` にした。

### 2026-07-06 助動詞will/can編の書き換え表現と余白調整

`中学生英作文助動詞will編.xlsx` と `中学生英作文助動詞can編.xlsx` では、助動詞本体と書き換え表現を同じ教材内で扱った。

今回の失敗・修正の過程:

1. 最初の作成時に、`will` / `can` と `be going to` / `be able to` の言い換え表現を入れたが、書き換え後の疑問文への返答と、否定短縮形の一部確認が後追いになった。
2. 特に「いいえ」の返答では、基本形だけでなく短縮形も必要になる。`will not` / `won't`、`cannot` / `can't` だけでなく、`is not going to` / `isn't going to`、`are not able to` / `aren't able to` など、書き換え表現側の短縮形も点検する。
3. 返答行や短縮形を後から差し込むと、行数、行高、改頁、ページ内余白のすべてを再調整する必要が出る。今後は、作成前に「肯定文・否定文・疑問文・Yes/No返答」ごとの基本形・短縮形・言い換えを表にしてからレイアウトへ進む。
4. 余白を詰めるためにシート側の縮小を先に使うと、文字サイズとページ密度の判断が難しくなり、結果として遠回りになった。
5. ユーザーが解答シート1ページ目を100%基準で手動調整し、不要列を削除した状態が基準として有効だった。今後は、縮小率ではなく、不要列の削除、印刷範囲、列幅、行高の順で整える。
6. 最終確認では、両ファイルとも最大列を `G` までにし、印刷範囲を `$A$1:$G$191`、全行結合を `A:G` にそろえた。改頁は `[44, 86, 128, 170]` のまま維持できた。

次回以降の作成前チェック:

- 助動詞本体と書き換え表現の両方について、肯定文、否定文、疑問文、Yes/No返答を列挙する。
- 否定文と「いいえ」の返答では、基本形だけでなく短縮形も必ず列挙する。
- 書き換え表現側の短縮形を忘れない。`be going to` と `be able to` は主語に応じて `am/is/are` が変わる。
- 行を追加する前に、問題シートと解答シートの同じ位置に入るか確認する。
- 余白が大きいときは、縮小率を下げる前に、100%基準で不要列、印刷範囲、列幅、行高、改頁を見直す。

### 2026-07-08 現在完了形経験用法の返答省略ミス

`中学生英作文現在完了形_経験用法編.xlsx` では、経験用法として `visited Kyoto before`、`four times`、`How many times ...?` を扱った。

今回の反省:

1. `Have you ever visited Kyoto?` や `How many times have you visited Kyoto?` への否定返答で、`I have not.` / `I haven't.` のように後ろを省略できることに最初から気づけなかった。
2. これは単なるレイアウト修正ではなく、英語として返答がどこまで自然に省略できるかをAI側が先に確認すべき内容だった。
3. `No, I have never visited Kyoto.` のような `never` 行は目的語句まで必要なので全文のままにする。一方で、`have not` / `haven't` の行は `No, I have not (visited Kyoto before).`、`No, I haven't (visited Kyoto before).` のように、省略可能な部分を括弧で示す。
4. Yes/No疑問文への `No` 返答だけでなく、`How many times ...?` への「一度もありません」の返答でも同じ省略が起こるため、両方の系統を同時に確認する。
5. 今後、現在完了形の完了・経験・継続・結果用法を扱うときは、英文の正誤だけでなく「短く答えた場合に残せる部分」「括弧で任意扱いにする部分」を先に列挙してからレイアウトへ入る。

### 2026-07-09 例文追加時に既存例文を書き換えた件

経験用法の「～したことがある」に「何回～したことがあるか」の例文を加える依頼に対し、追加先を確保するために既存の「～したことがある」系統を確認なく書き換えた。これは、内容上の整合性だけを優先し、ユーザーが残したい既存例文と追加したい新しい系統を区別しなかった判断ミスである。

今後の規則:

1. 「加える」「追加する」「残す」は、既存内容を保持したまま新しい内容を足す指示として扱う。
2. 既存例文の削除・置換・意味変更は、ユーザーが明示した場合に限る。
3. 既存内容と追加内容を同じページに収めにくいなど、両立に問題がある場合は、勝手に置換せず事前に確認する。
4. 編集後は、追加した例文だけでなく、追加前の主要例文が問題・解答の両シートに残っているか検査する。
5. 現在完了形の経験用法では、「訪れたことがありますか」のYes/No系統と、「何回訪れたことがありますか」の回数系統を別系統として保持する。一方を加えるために他方を書き換えない。

### 2026-07-09 継続用法の `since` 区切り・見出し書式のやり直し

`中学生英作文現在完了形_継続用法編.xlsx` に `for` と `since` の2系統を配置した際、経験用法編の29行レイアウトを流用したが、行の役割と書式の対応を十分に検査しなかった。その結果、`【since】8歳のときから住んでいる` の区切り用太罫線と見出し用12pt書式が、後続の例文・回答欄側へずれた。

修正過程で得た反省:

1. `太線` はセル罫線、`太字` は文字書式として別々に扱う。似た表現でも、`Border` と `Font` のどちらを変更する指示かを明示してから編集する。
2. 今回「太字」と呼ばれた見た目は、実際には `font.bold = False` のまま、見出し用12pt書式が回答欄へずれていた。表示上の強調は、太字フラグだけでなく書体・サイズ・斜体も確認する。
3. 派生テンプレートを使う場合は、行番号ではなく「主語見出し・注意書き・小見出し・本文・回答欄」という役割ごとに書式を割り当てる。
4. `【for】` と `【since】` のような対になる小見出しは、フォント、行高、上罫線を相互比較する。最初の小見出しだけ正しければ完了としない。
5. 結合セルでは、隣接行の下罫線と上罫線が重なり、内部では `thin` でもPDF上で太く見える場合がある。アンカーセルの値だけで判断せず、A:J全体と隣接する上下両辺を調べる。
6. `openpyxl` の内部検査後、Excel COMでPDF化し、問題・解答の代表ページをPNGで目視する。今回も、この工程で旧位置の濃い線が残ることを検出できた。
7. 書式修正は一時ファイルへ保存してから対象ファイルを置換し、検査に失敗した途中状態を本体へ残さない。

確認例:

- Yes/No疑問文: `No, I have not (visited Kyoto before).` / `No, I haven't (visited Kyoto before).`
- 回数疑問文へのゼロ回答: `I have not (visited Kyoto before).` / `I haven't (visited Kyoto before).`
- `never` 行: `I have never visited Kyoto.` のように全文で示す。

- まず内容確認を終える。助動詞名、分類、現代口語と文語の対応を列単位で一覧化し、重複・欠落を確認する。
- `たい` / `たがる`、`ている` / `てある`、断定 `なり` と伝聞・推定 `なり` のような混同しやすい組を重点確認する。
- 一度に多くの体裁指示を処理しない。内容、用紙、列幅、行高、改行・縮小表示、色の順に分ける。
- 印刷用の列幅は、最大1行・最大2行・最大3行のように分類基準を決めてからそろえる。
- セル内改行、折り返し、縮小表示、縦書き方向、固定行高を同時に使うと表示が不安定になりやすい。ダブルクリックしないと正しく表示されない場合は、縮小表示を外すことを最初に疑う。
- 体裁確認では、openpyxl上の値だけでなく、ユーザーの印刷ページ表示での見え方を重視する。

詳細は `日本語助動詞一覧_作業記録.md` に残した。

## 仕上げ工程で得た運用判断

Excel教材の微調整では、すべてをCodex側で自動処理するより、ユーザーがExcel上で直接触った方が早く確実な箇所がある。特に、空シート削除、斜線セルの細かな文字位置、表示上の微妙な見た目確認は、ユーザーの手作業とCodexの検証を組み合わせると効率がよい。

今回の最終仕上げでは次の方針が有効だった。

- ユーザーが手作業で直した箇所は、再生成や広範囲の整形で上書きしない
- Codexは、シート構成、タイトル、印刷範囲、余白、1ページ設定、数式エラーの有無など、見落としやすい機械的チェックを担当する
- 手動で削除済みの無駄なシートは、再度作成したり復元したりしない
- 縦型・横型のタイトル表記はそろえる
  - `週間学習計画表（縦型）`
  - `週間学習計画表（横型）`
  - `生活記録表（縦型）`
  - `生活記録表（横型）`
- タイトルは横型に近い見え方にするため、14pt・太字を基準にする

次回以降、似た作業では「自動化で直す部分」と「ユーザーが手で見た目を整える部分」を分けて進める。Codexは最後に整合性チェックを行い、必要なら `README.md` と `SKILL.md` に反映する。
