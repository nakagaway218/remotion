# X Client Pull Post Maker

## Core Rule

Treat client acquisition on X as a pull-based trust system, not a one-off viral post.

Do not write hard-sell posts first. Build posts that make readers think:

- This person understands my problem.
- This person has proof or a concrete process.
- I can imagine asking them for help.

Default mix: value 7, proof/social proof 2, personality 1. Direct promotion should be rare and indirect; types 1 and 5 below should carry most of the selling.

## Workflow

1. Interview the user before drafting unless enough context is already provided.
2. Identify the best buyer, problem, service, evidence, and safe claims.
3. Choose 1-3 post types from the six client-acquisition types.
4. Draft posts in Japanese for X.
5. Run the quality check and revise before final output.
6. If the user asks for daily continuity, create a 7-day or 14-day posting plan using the 7:2:1 mix.

## Interview

Ask up to 7 questions at once. Keep the questions easy and include examples. If the user seems unsure, say that "おまかせ" is acceptable.

Required questions:

1. 誰から相談が来てほしいですか？
   例: 中小企業の社長、士業、店舗オーナー、個人事業主、講師、制作会社、まだ未定
2. 何を解決する人として見られたいですか？
   例: AI導入、業務自動化、X運用、資料作成、LP制作、営業改善、採用改善
3. すでに見せられる実績や証拠はありますか？
   例: 数字、Before/After、画面、制作物、顧客の声、作業時間削減、なくても可
4. 売りたいサービスや相談導線は何ですか？
   例: 無料相談、診断、制作代行、顧問、講座、LINE登録、まだ未定
5. 投稿のトーンはどうしますか？
   例: やさしい、実務家っぽい、少し煽る、淡々とプロっぽい、親しみ重視
6. NG表現や避けたい見せ方はありますか？
   例: 断定しすぎない、稼げる連呼しない、実績を盛らない、顔出しなし
7. 今日作りたい本数は何本ですか？
   例: 3本、6本、10本、7日分

If the user already gave enough information, do not re-ask everything. Ask only for missing high-risk items, especially target buyer, proof, offer, and NG claims.

## Six Post Types

Use `references/post-types.md` for detailed formulas and examples.

1. Results / Before-After
   - Strongest for client acquisition.
   - Use numbers, screens, deliverables, or process evidence.
   - Never exaggerate. If exact numbers are unavailable, use qualitative proof.
2. Solution / Know-how
   - Solve the buyer's problem before they ask.
   - Show expertise through concrete steps, checks, templates, or mistakes.
3. Portfolio / Work Sample
   - Show what was built.
   - Show the work and end with a practical note, not engagement-bait questions.
4. Positioning / Profile
   - Make "who I help and what I solve" obvious at a glance.
   - Useful for pinned posts, self-introductions, and recurring positioning posts.
5. Client Voice / Order / Thanks
   - Use social proof to reduce buyer anxiety.
   - Protect privacy and avoid revealing client details without permission.
6. Work Style / Personality
   - Show reliability, speed, communication style, or values.
   - Use sparingly; skill parity is often decided by trust and personality.

## Drafting Rules

- Write in Japanese unless the user requests another language.
- Default to 120-280 Japanese characters per post.
- For longer posts, keep paragraphs short and readable on mobile.
- Start with a clear hook tied to the buyer's pain or desired result.
- Include one concrete detail: number, task, workflow, deliverable, screen, mistake, checklist, or decision.
- Do not force a CTA on every post. Prefer a useful closing line.
- Avoid engagement-bait questions:
  - "欲しい人いますか？"
  - "こういうの作りたい人いますか？"
  - "同じ悩みある人いますか？"
  - "必要な人いますか？"
  - "知りたい人いますか？"
- Avoid AI-like phrasing:
  - "非常に重要です"
  - "〜することができます"
  - "〜してみてください"
  - "〜がおすすめです"
  - "〜ということになります"
  - "〜という観点から"
  - "まとめると"
  - "ぜひ活用してください"
  - "導入より定着が大事です" when used as a generic closing line
- Prefer plain, specific endings:
  - "最初はこの3つだけで十分。"
  - "ここが決まると、AI化する順番が見える。"
  - "ツール選びは、その後でいい。"
  - "現場で続く形にしておく。"
- Avoid obvious ad language:
  - "今すぐ申し込んでください"
  - "絶対稼げます"
  - "誰でも簡単に月収〇〇"
  - unsupported claims
- Do not invent clients, numbers, screenshots, testimonials, or results.
- If proof is weak, convert the post into know-how, process, or work-in-progress.

## Output Format

For a normal request, output:

1. `前提整理`
   - target buyer
   - service or offer
   - usable proof
   - selected post types
2. `投稿案`
   - 3-10 posts, each with:
     - type
     - intent
     - post text
     - optional closing line
3. `おすすめ採用順`
   - which posts to publish first and why
4. `Record & Replay運用メモ` when relevant
   - how to use the posts in a daily scheduling workflow

For a 7-day plan, use the default ratio:

- Day 1: Solution / Know-how
- Day 2: Results / Before-After
- Day 3: Solution / Know-how
- Day 4: Portfolio / Work Sample
- Day 5: Positioning / Profile
- Day 6: Solution / Know-how
- Day 7: Work Style / Personality or Client Voice

## Quality Check

Before final output, check:

- Is it clear who the post is for?
- Is the post useful even if the reader never buys?
- Is there at least one concrete detail?
- Are proof claims supported by user-provided facts?
- Does the post avoid engagement-bait questions and forced CTAs?
- Does it avoid AI-like generic phrasing?
- Does the set follow roughly value 7, proof/social proof 2, personality 1?
- Would a potential client understand what to ask about?

If a draft fails, revise it silently before presenting it.
