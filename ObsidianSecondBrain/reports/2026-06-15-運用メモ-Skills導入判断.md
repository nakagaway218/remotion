# Skills導入判断メモ

## 結論

`claude-skills-installer-ja` は、Codexにそのまま大量導入するものではなく、「必要なskillだけ選び、安全確認して、自分の環境に合う形へ移植する」ための判断手順として取り込む。

Codexでは、Claude Code用の `~/.claude/skills/` 前提をそのまま使わない。必要な内容だけを次のどれかへ移す。

- リポジトリ共通: `AGENTS.md`
- Myownproject共通: `SKILL.md`
- Obsidian文脈: `ObsidianSecondBrain/reports/`
- 繰り返し作業: Codex skill
- 配布・共有する仕組み: Codex plugin

## 導入判断の流れ

### 1. まず業務を聞く

skillを探す前に、次を確認する。

- 主な業務は何か
- 毎日・毎週くり返している作業は何か
- 開発寄りか、文章/資料/データ処理寄りか
- 失敗すると困る作業は何か
- 個人用か、プロジェクト用か、将来共有したいか

### 2. 候補は3〜5個に絞る

「全部入れる」はしない。

よくある候補カテゴリ:

| 業務 | 候補の方向 |
|---|---|
| 企画・壁打ち | Brainstorming, Grill Me, PRD系 |
| 記事・文書 | Doc Co-Authoring, Edit Article, Research to Writing |
| 資料作成 | PPTX, Theme, XLSX |
| 書類整理 | PDF, DOCX, XLSX, document-processor |
| コード開発 | Git Guardrails, TDD, Systematic Debugging, QA |
| Obsidian | Obsidian Vault, MOC, wikilink運用 |

### 3. 安全確認を必ず挟む

外部skillは、`SKILL.md` でAIの行動を変える。導入前に次を確認する。

- 一次配布元が実在するか
- `SKILL.md` があるか
- frontmatterの `name` / `description` が壊れていないか
- 危険な操作が含まれていないか
- Git、削除、外部送信、認証情報、課金APIに触れないか
- ライセンス上、コピー・改変してよいか
- 参照元のフォルダ名が改名・廃止されていないか

### 4. Codexでは移植先を選ぶ

| 目的 | 置き場所 |
|---|---|
| このリポジトリの基本ルール | `AGENTS.md` |
| Myownproject全体の作業手順 | `SKILL.md` |
| Obsidianで読む運用メモ | `ObsidianSecondBrain/reports/` |
| 本当に繰り返す専用手順 | `C:\Users\nakag\.codex\skills\<skill-name>\SKILL.md` |
| 他者や別環境へ配る | plugin化を検討 |

### 5. まず1個だけ試す

導入は「まず1個、1週間使う」が原則。使ってから、足りない部分を自分用に編集する。

## Myownproject向けの優先候補

今の状況では、外部skillをすぐ大量導入する必要はない。すでにCodex側にPDF、文書、プレゼン、スプレッドシート、Google Drive系、ObsidianSecondBrain、AIWorkforceTemplateがある。

優先して検討するなら次の順番。

1. 企画の穴を見つける壁打ち系
2. 記事・台本・教材の構造編集系
3. Git事故防止やデバッグ手順などの安全装置系
4. Obsidian Vault運用のMOC/リンク整理系

## 使うときの依頼文

```text
この外部skill候補を、Codexで使うべきか判断してください。

目的:
- 

候補URL:
- 

確認してほしいこと:
- 何をするskillか
- 公式/非公式、ライセンス、安全面
- Myownprojectでは AGENTS.md / SKILL.md / ObsidianSecondBrain / Codex skill / plugin のどれに入れるべきか
- すぐ導入するか、参考メモに留めるか
```
