# チャット文脈保存ルール

このフォルダは、AI社員化、サブエージェント化、マルチエージェント、作業判断に関する重要なチャット文脈を残す場所です。

## 目的

- チャットだけで終わらせると失われる判断を、次回以降も読める形にする
- コミットが必要なくらいのやり取りをしたときに、背景、判断、未解決事項を残す
- 後から別のAIや別のチャットに引き継いでも、なぜその作業をしたか分かるようにする

## 保存する目安

次のどれかに当てはまる場合は、チャット文脈の保存を提案します。

- 新しいファイルや設計方針を追加した
- 既存の運用ルールを変えた
- 今後も繰り返す判断基準を決めた
- ユーザーの好み、禁止事項、確認ポイントが明確になった
- コミットする可能性がある程度の変更を行った
- 後から「なぜそうしたか」を説明する必要がありそう

小さな誤字修正、単発の軽い質問、保存する価値の低い一時メモでは不要です。

## 保存先の選び方

| 内容 | 保存先 |
| --- | --- |
| AI社員化、サブエージェント化、判断ガイド | `AIWorkforceTemplate/05_チャット文脈保存/` |
| キャリア、教育AI、事業化相談 | `CareerAIProject/chat_logs/` |
| 特定プロジェクトの作業経緯 | そのプロジェクト内の `handoff.md`、`log.md`、または `chat_logs/` |
| リポジトリ全体の固定ルール | `AI_CONTEXT.md`、`DESIGN.md`、`SKILL.md` に要点を反映 |

## 保存形式

ファイル名:

```text
YYYY-MM-DD_short-topic.md
```

推奨構成:

```markdown
# [タイトル]

日付: YYYY-MM-DD

## 相談内容

## 決めたこと

## 反映したファイル

## 今後の運用

## 未解決事項
```

## 分割して保存する

長いチャットや複数テーマを含む相談は、1つのMarkdownに無理に圧縮しません。

次のように分けます。

| ファイル | 役割 |
| --- | --- |
| `README.md` | 保存ルール、命名、参照先の入口 |
| `YYYY-MM-DD_topic.md` | その日の相談内容と決定事項 |
| `handoff.md` | 次回作業者への引き継ぎ |
| `unresolved.md` | 未解決事項だけを分離 |
| 各プロジェクトのREADMEやAI_WORKFORCE.md | 実際の運用ルールとして反映する要点 |

分割するときの基準:

- 相談の背景と決定事項は、日付付きログに残す
- 次に作業する人が最初に読むべきことは、`handoff.md` に分ける
- まだ判断できないことは、`unresolved.md` に分ける
- 実際に今後の作業ルールになる内容は、該当プロジェクトのREADME、`AI_WORKFORCE.md`、`WORKFORCE_SPEC.md`、または `SKILL.md` に反映する
- 日付付きログには、関連ファイルへのリンクや相対パスを書いて連携できるようにする

目標は、短くしすぎることではなく、次回のAIや人間が必要な粒度で読み分けられることです。

## 今後の習慣

コミットが必要なくらいのやり取りをした場合、作業完了前に次を確認します。

```text
今回のやり取りは、次回以降の判断に使えるコンテキストとして残しますか？
```

ユーザーが明示的に「残して」と言った場合は、要約したMarkdownを保存し、必要なら `AI_CONTEXT.md`、`DESIGN.md`、`SKILL.md`、該当プロジェクトのREADMEから参照できるようにします。
