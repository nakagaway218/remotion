# AI社員化・サブエージェント化 判断ガイド

このガイドは、「サブエージェント化」「AI社員化」「マルチエージェント」のどれを使うべきか迷ったときの相談用メモです。

## まず結論

毎回 AI 社員化する必要はありません。

- 1回だけの小さな作業: 通常の Codex 依頼で十分
- 作業の一部だけ専門的に分けたい: サブエージェント化
- 今後も繰り返す業務として残したい: AI社員化
- 工程が多く、調査・作成・レビューを分けないと品質が落ちる: マルチエージェント運用

## 用語の使い分け

| 言葉 | 意味 | 向いている場面 |
| --- | --- | --- |
| サブエージェント化 | 作業の一部を専門役に分けること | 調査、レビュー、テスト、整形などを切り出したい |
| AI社員化 | 継続的な役割、責任、入力、出力、確認点、引き継ぎを決めること | 同じ種類の作業を何度も行う |
| マルチエージェント | 複数の役割を順番または並行で連携させること | 大きな制作、調査、教材作成、複雑なレビュー |
| スキル化 | Codex が再利用できる手順として登録すること | 毎回同じ手順を正確に実行したい |
| コマンド化 | Claude Code などで呼び出しやすい入口を作ること | 人間が同じ流れを短い命令で開始したい |

## 判断チェック

次の質問で判断します。

| 質問 | はいの場合 |
| --- | --- |
| 同じ作業を今後も繰り返すか | AI社員化またはスキル化を検討 |
| 失敗したときの損失が大きいか | レビュー担当、監査担当、保全担当を置く |
| 調査、作成、レビューの観点が混ざりやすいか | サブエージェント化またはマルチエージェント化 |
| 成果物の形式や保存先を毎回そろえたいか | AI社員化またはコマンド化 |
| 人間の承認ポイントが必要か | AI社員化に向いている |
| 1回だけの軽い修正か | 通常依頼で十分 |

## おすすめの依頼文

迷ったときは、いきなり「AI社員化して」と言わず、次のように相談します。

```text
この作業は、通常依頼・サブエージェント化・AI社員化・スキル化のどれがよいか判断してください。
理由と、残すべきファイルがあるかも教えてください。
```

作業を始める前に確認したい場合:

```text
このタスクは一回限りか、今後も使う仕組みにするべきか相談したいです。
過剰なAI社員化にならないように、最小構成を提案してください。
```

過去の作業を見直す場合:

```text
既存のAI_WORKFORCE.md、WORKFORCE_SPEC.md、.claude/agents、.claude/commandsを棚卸しして、
残す・統合する・簡略化する・保留に分けてください。
```

## 最小構成の目安

### 通常依頼で十分

- 誤字修正
- 小さなREADME修正
- 単発の調査メモ
- 1つのファイルだけの軽い変更

### サブエージェント化が向いている

- 調査だけを別視点で確認したい
- レビューだけ厳しくしたい
- テスト観点だけ洗い出したい
- Git 状態やファイル移動リスクだけ確認したい

### AI社員化が向いている

- 記事制作、台本制作、教材作成、買い物リスト更新のように繰り返す
- 役割、入力、出力、禁止事項、引き継ぎを明文化したい
- 別のAIや別のチャットに引き継ぐ可能性が高い
- 過去に同じ種類の失敗があり、再発防止ルールを残したい

### マルチエージェント運用が向いている

- 調査量が多い
- 制作物の品質確認が重要
- 工程ごとに判断基準が違う
- 一人のAIに任せると、調査、創作、レビューが混ざってしまう

## 見直し基準

既存の AI 社員化ファイルは、次の4分類で見直します。

| 分類 | 判断 |
| --- | --- |
| 残す | 実際に繰り返し使う、失敗防止に効いている |
| 統合する | 似た役割が複数あり、1つにまとめた方がよい |
| 簡略化する | 役割が多すぎる、実作業より管理が重い |
| 保留する | 現時点では使っていないが、消す判断も早い |

## Myownproject での暫定評価

| 領域 | 暫定評価 | 理由 |
| --- | --- | --- |
| `AIWorkforceTemplate/` | 残す | 共通の型として有効。過剰運用を避ける説明もある |
| `Webarticle/` | 残す | 調査、構成、本文、レビュー、整形の分離が自然 |
| `Scenariowriting/` | 残す | 台本制作は工程が多く、分担の効果が出やすい |
| `ShoppingList/` | 残す | 過去の失敗防止、削除リスク審査、Excel様式保全に意味がある |
| `Mytool/` | 簡略運用 | 小さい修正では全員を使わず、調査、実装、確認だけでよい |
| `teaching materials/` | 残す | 教材は難易度、解答、著作権、印刷形式の確認が必要 |
| `CareerAIProject/` | 残す | 長期方針と公開可否判断が必要 |

## 注意

- AI社員化は、作業を重くするためではなく、判断と引き継ぎを楽にするために使います。
- 「役割名を増やすこと」自体は成果ではありません。
- 小さい作業では、最小人数で進めます。
- GitHub に反映する前は、公開してよい内容か必ず確認します。
- `REQUIREMENTS_DEFINITION.md` が存在しない作業環境では、代わりに `WORKFORCE_SPEC.md` を簡易要件定義として使います。
