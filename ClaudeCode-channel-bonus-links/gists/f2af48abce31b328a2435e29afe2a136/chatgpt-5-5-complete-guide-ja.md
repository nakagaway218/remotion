## 0. まず結論

- 正式名称としては「ChatGPT-5.5」ではなく、OpenAIが発表している中心名称は「GPT-5.5」。ChatGPT上では主に「GPT-5.5 Thinking」や「GPT-5.5 Pro」として使われる。
- GPT-5.5は2026-04-23に発表された、実務・コーディング・調査・データ分析・文書/表計算・コンピュータ操作・長時間エージェント作業を強く意識したモデル。
- ChatGPTではGPT-5.3 Instantが全ログインユーザー向けの基本体験で、複雑なタスクではGPT-5.5 Thinkingへ自動切り替えされることがある。
- GPT-5.5 ThinkingはPlus / Pro / Business / Enterprise向けに展開中。GPT-5.5 ProはPro / Business / Enterprise / Edu向けの最上位オプション。
- CodexではGPT-5.5がPlus / Pro / Business / Enterprise / Edu / Goで利用可能。Codex内では400Kコンテキスト、Fast modeも提供される。
- APIでは2026-04-24時点でGPT-5.5は「coming soon」。現在のAPI実装ではgpt-5.4を基本にし、GPT-5.5が有効化されたら差し替えるのが現実的。
- 価格予定はgpt-5.5が入力$5.00 / 1M tokens、キャッシュ入力$0.50 / 1M tokens、出力$30.00 / 1M tokens。gpt-5.5-proは発表ページで入力$30 / 1M、出力$180 / 1Mと案内されている。
- GPT-5.5は「うまく指示すれば一問一答を超えて、目的の分解、ツール使用、検証、修正、成果物化まで進める」方向に強い。
- 使いこなしのコツは、役割ではなく「成果物、判断基準、使ってよい情報源、検証方法、途中報告、停止条件」を明示すること。
- Codexでは、単にコードを書かせるより「リポジトリを読ませ、既存パターンに合わせ、テストを走らせ、差分を説明させる」依頼がよく効く。

## 1. 用語整理

### 1.1 GPT-5.5とChatGPTの関係

GPT-5.5はモデル名。ChatGPTはアプリ/サービス名。したがって、厳密には「ChatGPT-5.5」ではなく、「ChatGPTでGPT-5.5 Thinkingを使う」「ChatGPTでGPT-5.5 Proを選ぶ」と表現するのが近い。

OpenAI Help Centerでは、ChatGPT上の体験をおおむね以下のように説明している。

| 表示/概念 | 中身 | 主な用途 |
| --- | --- | --- |
| Instant | GPT-5.3 Instant | 日常的な質問、翻訳、説明、軽めの技術文書、情報探索 |
| Thinking | GPT-5.5 Thinking | 複雑な実務、調査、コード、ファイル分析、表計算、長い推論 |
| Pro | GPT-5.5 Pro | 最難関タスク、長時間ワークフロー、高精度が必要な仕事 |

注意点:

- Instantを選んでいても、複雑なタスクではChatGPTがGPT-5.5 Thinkingへ自動切り替えする場合がある。
- GPT-5.5 Thinking / Proは段階的展開なので、対象プランでも即時に見えない場合がある。
- GPT-5.5 Proでは、Help Center上でApps、Memory、Canvas、image generationが利用できない旨が示されている。普段のChatGPTツールを全部使いたい場合はThinkingのほうが扱いやすい場面がある。

### 1.2 GPT-5.5の位置づけ

OpenAIの発表では、GPT-5.5は「実際の仕事をコンピュータ上で進める」方向に強いモデルとして説明されている。具体的には以下が中心。

- コードの作成、デバッグ、レビュー
- オンライン調査
- データ分析
- ドキュメントやスプレッドシートの作成/編集
- ソフトウェアの操作
- ツールをまたいだ作業
- 長い作業の計画、検証、継続
- 科学研究や専門的分析の初期支援

従来型の「質問に答えるモデル」から、「目的を受け取り、作業に分解し、使えるツールを選び、途中で検証し、完了まで進めるモデル」へ寄っている。

## 3. GPT-5.5は何が新しいのか

### 3.1 実務エージェント性能

GPT-5.5の特徴は、一つの問いに答えるだけではなく、仕事の目的を理解して、必要な順序で作業し、ツールを使い、検証しながら進める力にある。

典型的には以下のようなタスクで強みが出る。

- 「この市場を調べて、競合表、顧客セグメント、リスク、Go-to-market案までまとめて」
- 「このCSVを読み、異常値を見つけ、原因仮説を出し、グラフとレポートを作って」
- 「このリポジトリでバグを直し、既存テストを確認し、必要ならテストを追加して」
- 「このPDF群を横断して、矛盾点、未決事項、意思決定ログをまとめて」
- 「このUIを実装して、ブラウザで見た目を検証し、レイアウト崩れを直して」

### 3.2 コーディング性能

公式発表の評価例:

| 評価 | GPT-5.5 | GPT-5.4 |
| --- | ---: | ---: |
| SWE-Bench Pro Public | 58.6% | 57.7% |
| Terminal-Bench 2.0 | 82.7% | 75.1% |
| Expert-SWE Internal | 73.1% | 68.5% |

数値差以上に重要なのは、Codexタスクで「少ないトークンで完了しやすい」「長いタスクを進めやすい」と説明されている点。つまりコーディングでは、単発の関数生成よりも、既存コードの読解、複数ファイル編集、テスト実行、差分説明、レビュー対応のようなワークフローで価値が出やすい。

### 3.3 コンピュータ操作とツール利用

公式発表ではOSWorld-Verified、BrowseComp、MCP Atlas、Toolathlonなど、コンピュータ利用やツール利用系の評価が示されている。

| 評価 | GPT-5.5 | GPT-5.4 |
| --- | ---: | ---: |
| OSWorld-Verified | 78.7% | 75.0% |
| BrowseComp | 84.4% | 82.7% |
| MCP Atlas | 75.3% | 70.6% |
| Toolathlon | 55.6% | 54.6% |
| Tau2-bench Telecom | 98.0% | 92.8% |

ここで見るべきポイントは、GPT-5.5が「調べる」「アプリを操作する」「ツールを選ぶ」「結果を使って次に進む」能力を強化していること。

### 3.4 専門業務

公式発表のProfessional系評価例:

| 評価 | GPT-5.5 | GPT-5.4 |
| --- | ---: | ---: |
| GDPval wins or ties | 84.9% | 83.0% |
| FinanceAgent v1.1 | 60.0% | 56.0% |
| Investment Banking Modeling Tasks Internal | 88.5% | 87.3% |
| OfficeQA Pro | 54.1% | 53.2% |

実務では、以下のような使い方が現実的。

- 財務モデルの前提チェック
- 契約書や仕様書の論点抽出
- 顧客サポートFAQの改善
- スプレッドシートの監査
- 営業資料や稟議書のドラフト
- 調査メモから意思決定用サマリーへの変換

ただし、金融・法務・医療など高リスク分野では、GPT-5.5の出力をそのまま意思決定に使わず、人間の専門家レビューを入れるべき。

### 3.5 学術・科学研究

公式評価ではFrontierMath、GPQA Diamond、Humanity's Last Exam、GeneBench、BixBenchなどが示されている。GPT-5.5は特に「大量文献やデータを読み、仮説を作り、分析ワークフローを進める」支援に向いている。

適した用途:

- 論文リストの要約と分類
- 研究仮説の整理
- 実験計画のレビュー
- データ解析コードの作成
- 結果の解釈候補の列挙
- 図表や補足資料の作成

適さない用途:

- 未検証の実験結果を事実として断定
- 安全性に関わるプロトコルの自動実行
- 医療・バイオ・セキュリティ上危険な手順の詳細化
- 研究倫理や法規制を無視した提案

## 4. ChatGPTでの使い方

### 4.1 Instant、Thinking、Proの選び方

| 状況 | 推奨 |
| --- | --- |
| 軽い質問、翻訳、短い文章修正 | Instant |
| 調査、ファイル分析、複数条件の判断 | Thinking |
| 難問、長い推論、高精度の分析 | Pro |
| コードベース編集、テスト実行、PRレビュー | Codex |
| アプリに組み込む | API、現時点はgpt-5.4中心 |

### 4.2 Thinking timeの使い分け

Help Centerでは、GPT-5.5 Thinking選択時にThinking time toggleが表示されると説明されている。

| 設定 | 向いている場面 |
| --- | --- |
| Light | 速さ優先、そこまで難しくない推論 |
| Standard | 通常の推奨。速度と賢さのバランス |
| Extended | より深い検討、重要な文章や調査 |
| Heavy | Pro向け。難問、長時間、高精度重視 |

使い分けの目安:

- 会議メモ整形: Light / Standard
- 企画案比較: Standard / Extended
- 契約書のリスク洗い出し: Extended / Heavy
- コードベース全体の設計変更: Codex + GPT-5.5、またはHeavy相当の長時間作業

### 4.3 途中で指示を追加できる

Help Centerでは、GPT-5.5 Thinking / Proが推論開始時に短いpreambleを表示する場合があり、モデルが考えている間に追加指示で方向修正できると説明されている。

実務ではこれがかなり重要。

途中介入の例:

```text
方針は良いです。ただし今回はスピードより正確性を優先してください。
出典が確認できない情報は「未確認」に分類してください。
```

```text
競合比較は日本市場に限定してください。
海外事例は別枠の参考として扱ってください。
```

```text
コード修正に入る前に、既存テストと影響範囲を先に確認してください。
```

## 5. 良いプロンプトの基本型

GPT-5.5では「賢いから短く投げればよい」より、「任せる範囲を明確にして、検証条件を置く」ほうが強い。

### 5.1 基本テンプレート

```text
目的:
{最終的に達成したいこと}

背景:
{前提、読者、制約、現在の状況}

入力:
{貼り付けるデータ、ファイル、URL、メモ}

やってほしいこと:
1. {タスク1}
2. {タスク2}
3. {タスク3}

出力形式:
{表、箇条書き、Markdown、JSON、スライド構成、コード差分など}

判断基準:
{何を重視するか。正確性、速度、網羅性、実装容易性、リスク低減など}

検証:
{出典確認、計算チェック、テスト実行、反例検討など}

不明点の扱い:
{推測しない、仮説として分ける、先に質問する、など}
```

### 5.2 GPT-5.5向けの指示の書き方

良い指示:

```text
この依頼は複数ステップです。まず作業計画を短く立て、次に必要な情報を確認し、最後に成果物を作ってください。
途中で不明点があっても、合理的な仮定で進められる場合は仮定を明示して進めてください。
重大な不確実性だけ質問してください。
```

良い指示:

```text
回答前に、出力の品質を自己チェックしてください。
チェック観点は、事実の根拠、抜け漏れ、計算ミス、読者にとっての使いやすさです。
最終回答には内部思考ではなく、検証結果の要点だけを書いてください。
```

良い指示:

```text
このタスクでは、完璧な一般論よりも、実行可能な具体案を優先してください。
それぞれの提案について、最初の一手、必要な材料、失敗しやすい点、成功判定を示してください。
```

避けたい指示:

```text
いい感じに全部やって。
```

避けたい理由: GPT-5.5はかなり補完してくれるが、評価基準が曖昧だと「良さ」の方向がズレる。

## 6. 事例と詳細プロンプト集: 調査・戦略

### 6.1 市場調査レポート

用途: 新規事業、投資検討、競合分析、経営会議資料。

```text
目的:
日本市場における{製品/サービス名}の参入可能性を判断するための市場調査レポートを作成してください。

背景:
- 読者は経営陣です。
- 最終的には参入するか、見送るか、追加調査するかを判断します。
- 机上の一般論ではなく、意思決定に使える粒度にしてください。

調査範囲:
- 市場規模と成長要因
- 顧客セグメント
- 既存競合と代替手段
- 価格帯
- 規制、法務、商習慣
- 流通チャネル
- 参入障壁
- 3年後のシナリオ

やってほしいこと:
1. まず調査計画を作る
2. 必要に応じてWeb検索し、信頼できる情報源を優先する
3. 競合を表で比較する
4. 顧客セグメントを優先順位付きで整理する
5. 参入戦略を3案出す
6. 各案のリスク、初期コスト、実行難易度、期待リターンを評価する
7. 最後に推奨結論を1つ出す

出力形式:
- Executive Summary
- Key Findings
- Market Landscape
- Competitor Table
- Customer Segments
- Entry Strategy Options
- Risks and Unknowns
- Recommendation
- Sources

制約:
- 出典が弱い情報は「仮説」と明記してください。
- 数値は必ず出典または算出根拠を添えてください。
- 日本市場と海外市場を混同しないでください。
```

### 6.2 競合比較表

```text
以下の競合について、購入検討者が比較しやすい表を作ってください。

対象:
- {競合A}
- {競合B}
- {競合C}
- {自社/自分の案}

比較軸:
- ターゲット顧客
- 主要機能
- 強み
- 弱み
- 価格
- 導入難易度
- サポート
- 既存ユーザーの評判
- 差別化ポイント

追加依頼:
1. 公式サイト、レビュー、ニュースを分けて確認してください。
2. 明確な根拠がない項目は「未確認」としてください。
3. 最後に、自社が勝てるポジションを3つ提案してください。
4. それぞれのポジションに必要なプロダクト改善とマーケ施策を示してください。

出力:
Markdown表と、意思決定者向けの短い解説。
```

### 6.3 経営会議向け意思決定メモ

```text
あなたは経営企画のシニアアナリストです。
以下の材料をもとに、経営会議で10分で読める意思決定メモを作成してください。

決めたいこと:
{意思決定テーマ}

現状:
{現状の説明}

選択肢:
{選択肢A}
{選択肢B}
{選択肢C}

制約:
{予算、人員、期限、法務、既存顧客への影響など}

評価観点:
- 事業インパクト
- 実行可能性
- リスク
- 可逆性
- 顧客価値
- チーム負荷

出力形式:
1. 結論
2. 背景
3. 選択肢比較表
4. 推奨案
5. 推奨案を選ぶ理由
6. 想定される反論と回答
7. 30日以内のアクション
8. 決裁者に確認すべき論点

注意:
- 曖昧な表現を避けてください。
- 不確実性は隠さず、意思決定に必要な形で提示してください。
- 最後に「今決めるべきこと」と「後で決めればよいこと」を分けてください。
```

## 7. 事例と詳細プロンプト集: 文書・資料作成

### 7.1 長文メモから報告書へ

```text
以下の雑多なメモを、社内共有用の正式な報告書に整理してください。

読者:
{部門、役職、前提知識}

目的:
読者が状況を理解し、次のアクションを判断できるようにすること。

入力メモ:
{ここにメモを貼る}

作業:
1. メモを論点別に分類する
2. 重複を統合する
3. 不明点と矛盾点を抽出する
4. 必要に応じて表にする
5. 報告書として自然な順序に並べ替える

出力形式:
# タイトル
## 要約
## 背景
## 現状
## 主要論点
## リスク
## 未確認事項
## 推奨アクション
## 付録: 元メモからの対応関係

条件:
- 元メモにない事実を追加しないでください。
- 推測した箇所は「推測」と明示してください。
- 意思決定に不要な細部は付録へ回してください。
```

### 12.1 Codexとは

Codexは、コードを書く・読む・直す・レビューするためのAIコーディングエージェント。OpenAI Help Centerでは、ローカルツールでペア作業することも、クラウドに作業を委任することもできると説明されている。

- Codex app

### 12.2 Codex appの特徴

OpenAIのCodex app発表では、Codex appは「複数エージェントを管理するコマンドセンター」として位置づけられている。

主な機能:

- 複数エージェントを並列実行

- built-in worktree support
- Skills

- Personality設定
- Windows対応

### 12.3 Codex for almost everything

2026-04-16のOpenAI発表では、Codexがコード以外にも広がったことが説明されている。

新しい方向性:

- Mac上のアプリを見て、クリックし、入力するbackground computer use
- 複数エージェントが並列にMac上で作業
- app内ブラウザでフロントエンドやゲームを確認
- 画像生成モデルを使ったビジュアル作成
- 90以上の追加プラグイン
- 記憶、過去アクションからの学習、継続的/定期的な作業

つまりCodexは「コードを書くツール」から「コンピュータ上の仕事をコードとツールで進める作業環境」に広がっている。

### 12.4 GPT-5.5 in Codex

GPT-5.5発表によると、CodexでのGPT-5.5は以下。

- Plus / Pro / Business / Enterprise / Edu / Goで利用可能
- 400Kコンテキスト
- Fast modeあり
- Fast modeは生成トークンが1.5倍速く、コストは2.5倍
- GPT-5.4より高価格だが、タスク完了に必要なトークンが減る場面があると説明されている

### 12.5 Codex rate card

Help CenterのCodex rate cardでは、2026-04-02以降、Codex pricingがメッセージ単位ではなくAPI token usageに近い形式へ更新されたと説明されている。2026-04-23には既存Enterpriseにも反映された。

新しいtoken-based pricingの例:

| Model | Input tokens | Cached input | Output tokens |
| --- | ---: | ---: | ---: |
| GPT-5.5 | 125 credits / 1M | 12.50 credits / 1M | 750 credits / 1M |
| GPT-5.4 | 62.50 credits / 1M | 6.250 credits / 1M | 375 credits / 1M |
| GPT-5.4-Mini | 18.75 credits / 1M | 1.875 credits / 1M | 113 credits / 1M |
| GPT-5.3-Codex | 43.75 credits / 1M | 4.375 credits / 1M | 350 credits / 1M |

実務上は、出力の多い長時間タスクやFast modeはクレジット消費が大きくなりやすい。大規模作業では、最初に探索、次に限定実装、最後に検証という粒度で依頼すると無駄が減る。

## 14. API開発者向け整理

### 14.1 現時点の実装方針

2026-04-24時点では、GPT-5.5 APIはまだcoming soon。したがって、API開発者は以下の設計にしておくと移行しやすい。

- モデル名を環境変数に逃がす
- `gpt-5.4`を現在のデフォルトにする
- GPT-5.5公開後に`gpt-5.5`へ差し替える
- 高精度向けに`gpt-5.5-pro`を別設定にする
- レスポンス形式はStructured Outputsで固定する
- ツール利用はResponses API + function calling / built-in toolsを使う
- プロンプトはバージョン管理する
- 評価セットを用意して移行前後を比較する

### 14.2 Node.js最小例

現在は`gpt-5.4`で動かし、GPT-5.5 API公開後に環境変数を差し替える想定。

```javascript
import OpenAI from "openai";

const client = new OpenAI();

const model = process.env.OPENAI_MODEL ?? "gpt-5.4";

const response = await client.responses.create({
  model,
  input: [
    {
      role: "system",
      content:
        "You are a concise, careful business analyst. Separate facts, assumptions, and recommendations.",
    },
    {
      role: "user",
      content:
        "Summarize the risks and opportunities of entering the Japanese B2B SaaS market for AI meeting notes.",
    },
  ],
});

console.log(response.output_text);
```

### 14.3 将来のGPT-5.5切り替え例

```bash
export OPENAI_MODEL="gpt-5.5"
node app.js
```

Pro相当を使う場合:

```bash
export OPENAI_MODEL="gpt-5.5-pro"
node app.js
```

注意: これはGPT-5.5 API提供開始後の想定。公開前に本番で使えるとは限らない。

### 14.4 Structured Outputs設計

OpenAI API Docsでは、Structured Outputsは指定したJSON Schemaにモデル出力を従わせる機能として説明されている。実務アプリでは、自由文よりも構造化出力にしたほうが後続処理が安定する。

```text
次の顧客問い合わせを分類してください。

分類カテゴリ:
- billing
- bug
- feature_request
- cancellation
- sales
- other

返すJSON:
{
  "category": "...",
  "priority": "low | medium | high | urgent",
  "summary": "...",
  "customer_sentiment": "negative | neutral | positive",
  "needs_human": true,
  "reason": "..."
}

条件:
- JSON以外を返さない
- 判断できない場合はcategoryをotherにする
- 緊急度の理由をreasonに短く書く

問い合わせ:
{問い合わせ本文}
```

### 14.5 Function Calling設計

Function callingは、モデルを外部システムやアプリのデータに接続するための仕組み。GPT-5.5系では、モデルが自力で調べるだけでなく、どのツールを使うべきか判断させる設計が重要。

```text
あなたは社内業務アシスタントです。
ユーザーの依頼を達成するために、必要な場合だけツールを使ってください。

利用可能なツール:
- search_customer(customer_id)
- get_invoice(invoice_id)
- create_refund_request(invoice_id, amount, reason)
- search_docs(query)

ルール:
- 個人情報は必要最小限だけ扱う
- 返金は必ず請求書情報を確認してから提案する
- ユーザーが明示的に承認するまで返金リクエストを作成しない
- 社内ポリシーが不明な場合はsearch_docsで確認する

出力:
- 実施した確認
- 判断
- 次に必要な承認
```

### 14.6 ツール利用エージェントのプロンプト

```text
目的:
ユーザーの調査依頼に対し、Web検索、ファイル検索、必要な社内ツールを使って根拠ある回答を作る。

方針:
1. まず質問を分解する
2. 必要な情報源を決める
3. 信頼できる情報源を優先する
4. 根拠を集める
5. 矛盾を確認する
6. 最後に要約、根拠、未確認事項を分けて出す

禁止:
- 出典不明の数値を断定しない
- 古い情報を最新として扱わない
- ユーザーが求めていない個人情報を取得しない

出力形式:
## Answer
## Evidence
## Unknowns
## Recommended next step
```

## 15. 使い分けガイド

### 15.1 ChatGPTを使うべき場面

- 調査と要約
- 文章作成
- ファイル分析
- 画像分析
- 企画の壁打ち
- 勉強
- 資料構成
- 軽めのコード相談

### 15.2 GPT-5.5 Thinkingを使うべき場面

- 複数資料の横断
- 長い推論
- データ分析
- 表計算作成
- Web検索を含む調査
- 失敗リスクがある重要な文章
- 論点が絡み合う意思決定

### 15.3 GPT-5.5 Proを使うべき場面

- 高精度が必要
- 長く考える価値がある
- 一回の回答の品質を最大化したい
- 難問や研究寄りの問題
- 複雑な設計判断

ただし、GPT-5.5 Proは一部ChatGPTツール制限があるため、ツールを多用するタスクではThinkingのほうが合う場合がある。

### 15.4 Codexを使うべき場面

- リポジトリを読ませたい
- ファイルを編集させたい
- テストを走らせたい
- PRレビューをさせたい

- 複数エージェントで並列作業したい
- 毎日/毎週の開発作業を自動化したい

### 15.5 APIを使うべき場面

- 自社アプリに組み込む

- 外部ツールと連携する
- 評価、ログ、ガードレールを管理したい

現時点ではgpt-5.4を使い、GPT-5.5公開後に移行を検討する。

## 16. GPT-5.5時代のプロンプト設計原則

### 16.1 任せる範囲を明確にする

悪い例:

```text
この件を調べて。
```

良い例:

```text
この件について、意思決定に必要な情報を調べてください。
まず論点を分解し、信頼できる情報源から根拠を集め、最後に推奨判断と未確認事項を分けてください。
```

### 16.2 出力形式を先に決める

```text
出力は以下の形式にしてください。

## 結論
## 根拠
## 代替案
## リスク
## 次のアクション

各セクションは最大5項目。
数値には根拠を添える。
```

### 16.3 検証条件を置く

```text
最終回答の前に、以下を確認してください。
- 数値に計算ミスがないか
- 出典と主張が対応しているか
- 古い情報を最新情報として扱っていないか
- 推測と事実が分かれているか
- 読者が次に何をすべきか明確か

最終回答には、検証結果の要点だけ含めてください。
```

### 16.4 不明点の扱いを決める

```text
不明点が出た場合:
- 進行に重大な影響がある場合だけ質問してください。
- 合理的な仮定で進められる場合は、仮定を明記して進めてください。
- 出典がない情報は「未確認」としてください。
```

### 16.5 長い作業では停止条件を明示する

```text
以下のどれかに該当したら作業を止めて、状況を報告してください。
- 必要な権限がない
- 情報源が矛盾している
- 実装が既存設計を大きく変える必要がある
- テストが環境依存で実行できない
- セキュリティまたは法務上の確認が必要
```

## 17. 実務テンプレート集

### 17.1 1時間で調査してほしい

```text
このテーマを1時間で調査する前提で、最大限実務に使えるアウトプットを作ってください。

テーマ:
{テーマ}

読者:
{読者}

目的:
{意思決定/企画/営業/開発など}

作業:
1. 最初に調査クエリを設計
2. 信頼できる情報源を優先
3. 重要事実を抽出
4. 競合/事例/リスクを整理
5. 未確認事項を分ける
6. 最後に推奨アクションを出す

出力:
- 5行サマリー
- 詳細メモ
- 表
- 重要な出典
- 未確認事項
- 次の調査計画
```

### 17.2 会議録からアクション抽出

```text
以下の会議メモから、決定事項、未決事項、アクションアイテムを抽出してください。

会議メモ:
{メモ}

出力:
## 決定事項
## 未決事項
## アクションアイテム
| タスク | 担当 | 期限 | 依存関係 | 確認事項 |
## リスク
## 次回会議のアジェンダ

条件:
- 担当や期限が不明な場合は「未設定」とする
- 推測で埋めない
- 重複するタスクは統合する
```

### 17.3 採用面接設計

```text
次の職種の採用面接を設計してください。

職種:
{職種}

レベル:
{ジュニア/ミドル/シニア/リード}

重視する能力:
- {能力1}
- {能力2}
- {能力3}

作ってほしいもの:
1. 面接全体の構成
2. 評価基準
3. 質問リスト
4. 深掘り質問
5. 実技課題
6. 良い回答/弱い回答の例
7. バイアスを避ける注意点

条件:
- 候補者体験を損なわない
- 実務に近い評価にする
- 違法または不適切な質問を含めない
```

### 17.4 契約書レビュー補助

```text
以下の契約書をレビューしてください。

目的:
事業部が法務に相談する前に、論点を整理すること。

レビュー観点:
- 支払条件
- 契約期間と解除
- 損害賠償
- 知的財産
- 秘密保持
- 個人情報
- 再委託
- SLA
- 管轄/準拠法
- 自社に不利な片務性

出力:
1. 重要リスク一覧
2. 条文番号ごとのコメント
3. 交渉すべき箇所
4. 法務に確認すべき質問
5. ビジネス上の判断ポイント

注意:
これは法的助言ではなく、論点整理です。
断定せず、専門家確認が必要な点は明示してください。
```

### 17.5 セキュリティレビュー補助

```text

{設計/コード/仕様}

観点:
- 認証
- 認可
- 入力検証
- セッション管理
- データ漏洩
- ログ
- 依存ライブラリ
- シークレット管理
- SSRF/XSS/SQLi/CSRF
- 権限昇格

出力:
## High risk
## Medium risk
## Low risk
## Missing information
## Recommended fixes
## Tests to add

条件:
- 攻撃手順の悪用可能な詳細化は不要
- 防御、検出、修正に焦点を当てる
- 具体的な修正案を示す
```

## 18. 失敗しやすい使い方

### 18.1 情報源を指定しない最新情報調査

最新情報では、情報源指定が重要。

悪い例:

```text
GPT-5.5について教えて。
```

良い例:

```text
OpenAI公式発表、OpenAI Help Center、OpenAI API Docsを優先して、GPT-5.5の最新情報をまとめてください。
非公式情報は参考扱いにし、公式情報と分けてください。
```

### 18.2 成果物の読者を指定しない

悪い例:

```text
この分析をまとめて。
```

良い例:

```text
読者はCFOです。
投資判断のために、数値根拠、リスク、代替案、推奨結論を中心にまとめてください。
```

### 18.3 検証を入れない

悪い例:

```text
コードを書いて。
```

良い例:

```text
コードを書いたあと、既存テストを実行し、失敗した場合は原因を調べて修正してください。
テストできない場合は、なぜできないかと手動確認手順を示してください。
```

### 18.4 いきなり巨大タスクを丸投げする

GPT-5.5は長い作業に強いが、巨大タスクでは段階を切るほうが成果が安定する。

推奨:

```text
このタスクは大きいので、まず作業分解だけしてください。
次に、最もリスクの高い部分から実装してください。
各段階で検証結果を出してください。
```

## 20. まとめ

GPT-5.5の本質は、単に「より賢いチャットモデル」ではなく、複雑な仕事をより少ない指示で進めるためのモデルという点にある。ChatGPTではGPT-5.5 Thinking / Proとして、Codexではソフトウェア開発とコンピュータ上の作業を進めるエージェントとして価値が出る。

現時点で最も実用的な使い分けは以下。

- 普段の質問はInstant
- 複雑な調査や文書/データ分析はGPT-5.5 Thinking
- 最難関の推論はGPT-5.5 Pro
- コードベース作業はCodex + GPT-5.5
- API組み込みは今はgpt-5.4、GPT-5.5 API公開後に切り替え

プロンプトでは、役割名よりも「目的、背景、入力、出力形式、判断基準、検証、不明点の扱い」を書く。Codexでは「読む、計画する、編集する、テストする、報告する」の流れを明示する。これだけでGPT-5.5の長所はかなり引き出しやすくなる。
