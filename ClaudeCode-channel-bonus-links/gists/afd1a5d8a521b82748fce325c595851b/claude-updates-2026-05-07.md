## 2. Claude Managed Agents の大型アップデート

**Claude Managed Agents** は、Anthropic がホストする「マネージド型」のエージェント実行基盤です。開発者は自前でジョブキュー、ワーカー、リトライ、状態管理を組まずに、Claude をベースにした自律エージェントを本番環境で動かせます。今回の発表で、その能力が大幅に拡張されました。

### 2.1 Dreaming（リサーチプレビュー）

**Dreaming** は今回新たに **リサーチプレビュー** として公開された機能です。名前のとおり、エージェントが「アイドル時間」や「明示的な思考フェーズ」において、過去のセッション・実行履歴・蓄積した知識を**バックグラウンドで再評価し、内省的に学習・整理する**ことを目的としています。

#### 想定される動作モデル

- **オフライン内省**: ユーザーリクエストがない時間帯に、過去の失敗ケース・成功ケースを振り返り、メモリやプロンプト構造を更新
- **プランの事前準備**: 翌日に予定されているタスクに備えて、必要な前提情報を収集・要約しておく
- **抽象化と一般化**: 個別事例の集合からパターンを抽出し、再利用可能なヒューリスティクスとして保持

#### なぜ重要か

従来の LLM エージェントは「リクエスト駆動」でしか動かず、セッション間の学習が原則として行われませんでした。Dreaming は、**人間でいう「睡眠中の記憶整理」**に相当する処理をエージェントに与えることで、長期運用するエージェントの**継続的改善**を可能にします。

#### リサーチプレビューであることの意味

- 本番ワークロードへの組み込みは推奨されない
- API・挙動・課金モデルが変更される可能性が高い
- フィードバックを Anthropic に提供することが期待されている
- まずは限定された実験用途で試すフェーズ

### 2.2 Outcomes（パブリックベータ）

**Outcomes** は、エージェントの実行結果に対して「**何をもって成功とするか**」を構造化して定義し、その達成度を計測・追跡する機能です。今回 **パブリックベータ** に昇格しました。

#### 主な能力

- **目標定義**: 自然言語または構造化スキーマで、タスクのゴールを定義
- **完了判定**: エージェントの最終出力が定義したゴールに到達しているかを自動評価
- **テレメトリ**: 成功率、部分達成率、失敗パターンを継続的に集計
- **回帰検出**: モデル更新やプロンプト変更前後で、達成率が劣化していないかを検知

#### ユースケース例

- カスタマーサポートエージェントが「初回応答で問題を解決した割合」を追跡
- データ抽出エージェントが「必須フィールドをすべて埋めた割合」を計測
- コードレビューエージェントが「指摘がマージされた割合」をフォローアップ

#### Outcomes が解決する課題

LLM エージェントの本番運用で最大の悩みは、「動いているように見えるが、本当に役に立っているのか分からない」という**評価のブラックボックス化**です。Outcomes はこの問題に対して、Anthropic が公式に推奨する**評価フレームワーク**を提供します。

### 2.3 Multiagent Orchestration（パブリックベータ）

**Multiagent Orchestration**（マルチエージェント・オーケストレーション）も今回 **パブリックベータ** になりました。複数のエージェントが役割を分担し、必要に応じて協調・並列実行・ハンドオフを行うための基盤です。

#### アーキテクチャパターン

| パターン | 用途 |
|---|---|
| **オーケストレータ・サブエージェント** | 1 つの統括エージェントが複数の専門エージェントにタスクを委譲 |
| **パイプライン** | 順次的にエージェントが処理をリレー（例: 調査 → 草案 → 校正） |
| **並列ファンアウト** | 同種タスクを複数エージェントで並列実行し、最後に集約 |
| **ピアツーピア討議** | 複数エージェントが議論して結論を収束させる（例: ディベート方式） |

#### 技術的な提供物

- **共有メモリ / 共有コンテキスト**: エージェント間で状態を引き渡す機構
- **ツール権限の継承・分離**: 親エージェントの権限をどこまで子に渡すかを制御
- **トレーシング**: マルチエージェント実行のフロー全体を可視化
- **コスト・レイテンシ最適化**: 並列度やモデル選択を動的に調整

#### 導入時の注意点

- マルチエージェント化は**常に正解ではない**。単一エージェントで十分なタスクを過剰に分割すると、レイテンシ・コスト・デバッグ難易度が増す
- 役割定義を明確にしないと、エージェント同士が同じ仕事を奪い合ったり、責任の押し付け合いが起きる
- 監査ログとトレース設計を最初から組み込むこと

### 2.4 Webhooks（パブリックベータ）

**Webhooks** が **パブリックベータ** になりました。Managed Agents の実行ライフサイクルにおける各種イベントを、外部システムにリアルタイムで通知できます。

#### 想定イベント

- エージェント開始・完了・失敗
- ヒューマンインザループ承認待ち
- Outcomes の達成・未達成
- 長時間実行（Workflow / Durable Execution）におけるチェックポイント

#### 統合先の例

- **Slack / Microsoft Teams / Discord**: チームへの通知
- **PagerDuty / Opsgenie**: 失敗時のオンコール通知
- **Linear / Jira / Asana**: タスク作成・更新
- **データウェアハウス（BigQuery / Snowflake / Databricks）**: テレメトリ蓄積
- **自前のバックエンド**: ビジネスロジックとの統合

#### セキュリティ面の論点

- Webhook 署名検証（HMAC）を必ず行うこと
- 受信側のエンドポイントは冪等に設計すること（同一イベントが複数回届く前提）
- リトライポリシーとデッドレターキューを把握しておくこと

## 3. SpaceX との戦略的パートナーシップとコンピュート拡張

Anthropic は **SpaceX とのパートナーシップ** に合意したと発表しました。これにより、**計算リソース（コンピュートキャパシティ）** が**大幅に増加**します。今回の SpaceX 案件は、ここ最近の他のコンピュート契約と合わせて、以下に直接反映されます。

### 利用上限の引き上げ対象

- **Claude Code**: 開発者向け CLI / IDE 拡張のレート制限・使用量上限
- **Claude API**: API 経由で Claude モデルを呼び出す際のレート制限・スループット

### この発表の戦略的意味

#### 1. 「コンピュート不足」がボトルネックである現実

2024 年以降、フロンティア LLM ベンダー各社にとって最大の制約は **GPU・電力・データセンター容量** です。モデルの賢さ以前に、ユーザーが要求するワークロードを物理的に捌けるかどうかが、サービス品質を決めています。Anthropic も例外ではなく、Claude Code の利用上限・API のレート制限がユーザー体験のボトルネックになる場面がありました。

#### 2. SpaceX 提携の意外性とインパクト

SpaceX は元来ロケット・衛星通信（Starlink）の企業ですが、近年は**データセンター・電力インフラ・地上局のコンピュート**にも事業を広げています。Anthropic との提携は、こうした SpaceX のインフラ資産を Claude のワークロードに振り向けるものと推測されます。

#### 3. ユーザーに直接届く改善

- Claude Code を多用する開発者は、レート制限に当たる頻度が下がる
- API ユーザーはバーストワークロードに耐えやすくなる
- Managed Agents の長時間実行・並列実行が現実的になる
- 結果として、後述のマルチエージェントや業界向けテンプレートが「動く」前提が整う

### 既存ユーザーがすべきこと

- **再見積もり**: これまで上限を理由に諦めていたワークロード（バッチ処理、リアルタイム ML パイプライン、エージェントの並列実行など）を再検討する
- **使用量ダッシュボードの確認**: 新しい上限がアカウントにいつ・どのように反映されるかを確認
- **SLA / 課金モデルの確認**: 上限引き上げが従量課金枠の拡大なのか、固定枠の引き上げなのかを把握する

## 4. 金融サービス向け Claude エージェントテンプレート

Anthropic は、**金融サービス（Financial Services）業界向けに、すぐに実行可能（ready-to-run）な Claude エージェントテンプレート**を新たに提供開始しました。

### 提供されるテンプレートのカテゴリ

| カテゴリ | 想定タスク |
|---|---|
| **ピッチ作成（Pitch building）** | 投資銀行のピッチブック、IR 資料、案件提案書のドラフト |
| **バリュエーションレビュー（Valuation reviews）** | DCF・類似会社比較・先例取引などのバリュエーションモデル検証 |
| **月次決算（Closing the books at month-end）** | 仕訳起票、勘定残高照合、変動分析、開示資料の準備 |
| **その他の業務** | 規制レポーティング、KYC/AML、リサーチサマリ、ミーティング議事録等 |

### 利用方法は 2 系統

#### A. Cowork / Claude Code にプラグインとしてインストール

- **Cowork**（Anthropic が提供する協働環境）または **Claude Code** から、プラグインとして導入
- アナリストやアソシエイトが**自分のワークスペースでインタラクティブに**使うのに向く
- 既存の業務ファイル・スプレッドシート・PDF と組み合わせやすい

#### B. クックブック（Cookbooks）を使い、Managed Agents として本番運用

- Anthropic 公式の **claude-cookbooks** リポジトリに含まれる実装サンプルを下敷きに
- **Managed Agents** に乗せて**サーバサイドで自律実行**
- バッチ処理・スケジュール実行・社内システムとの統合に向く
- Outcomes / Webhooks / Multiagent Orchestration といった今回の新機能と組み合わせると効果が大きい

### 金融業界がターゲットになった背景

#### 1. 高い ROI が見込める領域

金融サービスは、**人件費が高く・反復作業が多く・ドキュメント駆動**という、生成 AI の典型的な高 ROI 領域です。とくに以下のプロセスは、AI エージェントによる効率化余地が大きいと指摘されてきました。

- 投資銀行のピッチ準備（深夜残業の常態化）
- 月次・四半期決算のクロージング
- 規制対応（KYC、サンクションスクリーニング、開示）

#### 2. Anthropic のポジショニング

Anthropic は **安全性・コンプライアンス・透明性**を強く打ち出しており、規制が厳しい金融業界との相性が良いベンダーです。今回のテンプレート提供は、その強みを「**業界向けソリューション**」として可視化する戦略的な一手です。

#### 3. 「エージェント・テンプレート」というパッケージング

これまで企業が LLM を導入するときの障壁は、「**自社のワークフローにどう落とし込むか**」の設計コストでした。テンプレート化することで、PoC の立ち上がりが数日〜数週間に短縮され、IT 部門・業務部門の双方にとって導入判断がしやすくなります。

### 導入時に検討すべき論点

- **データレジデンシ**: 顧客データ・取引データを Managed Agents で扱う場合、どのリージョンで処理されるか
- **モデルアクセスログ**: 監査要件を満たすロギング設計
- **Human-in-the-loop**: バリュエーション結果や決算仕訳に対するレビュー承認フロー
- **既存システム連携**: ERP（Workday / Oracle / SAP）、データウェアハウス、ファイルサーバ、Bloomberg / FactSet / Refinitiv 等との統合
- **モデル更新時のリグレッション**: Outcomes 機能で達成率の劣化を継続監視

## 5. 今回の発表が示す戦略的方向性

3 つの発表を貫くテーマを整理すると、Anthropic の戦略は次のように読み取れます。

### 5.1 「単発の応答」から「継続的に働くエージェント」へ

Dreaming・Outcomes・Multiagent・Webhooks は、いずれも**長時間・継続的に動くエージェント**を支える機能です。これは「ChatGPT 的な対話」から「同僚としてのエージェント」へというプロダクトシフトを明確にしています。

### 5.2 評価可能性（Evaluability）への投資

Outcomes の存在は、Anthropic が「**評価できないものは本番に出せない**」という思想を持っていることを示します。エージェントが自律的に動くほど、評価フレームワークの重要性は増します。

### 5.3 インフラとプロダクトの両輪

SpaceX 提携は、ソフトウェア機能だけでなく**物理インフラの確保**が競争優位の本質であることを示しています。利用上限の引き上げという形でユーザーに即時還元されている点も重要です。

### 5.4 業界別テンプレートでの GTM 加速

金融サービス向けテンプレートは、今後**ヘルスケア・法務・公共・製造**など他業界にも展開される可能性が高い構造です。横展開しやすい「テンプレート + Managed Agents + 業界クックブック」の三点セットは、Anthropic の標準的な業界進出パターンになると見られます。

## 6. 開発者・組織が今すぐ取るべきアクション

### 個人開発者・スタートアップ

1. **Claude Code の利用上限を再確認**し、これまで諦めていた重い作業を再試行する
2. **Managed Agents の Webhooks** を Slack や自前バックエンドにつなぎ、エージェント実行を可視化する
3. **Outcomes** で自分のエージェントの成功率を計測し、プロンプト改善のサイクルに組み込む
4. **Multiagent Orchestration** をまずは「2 体構成」から試す（オーケストレータ + 1 サブエージェント）

### 中堅・大企業の AI 推進担当

1. **業界テンプレートの該当性評価**: 金融でなくとも、テンプレートのパターンを参考に自社業務を棚卸し
2. **Cowork / Claude Code の社内ライセンス整備**: 利用上限引き上げを機に、社内の利用ガバナンスを再設計
3. **Managed Agents への移行ロードマップ**: 自前ホスティングからマネージド型への移行 PoC
4. **Outcomes ベースの KPI 設計**: ビジネス KPI とエージェント Outcomes の対応関係を定義

### 金融機関

1. **テンプレートの実装内容を確認**し、自社のコンプライアンス基準に適合するかを評価
2. **PoC スコープの定義**: ピッチ作成 / バリュエーション / 月次決算のいずれか 1 つに絞ってスタート
3. **データ連携ポリシーの整備**: Managed Agents が扱うデータの分類・暗号化・保管方針を確定
4. **Human-in-the-loop の業務設計**: 監査・承認・例外処理のフローを業務側と合意

## 7. よくある質問（FAQ）

**Q1. Dreaming は今すぐ本番で使えますか？**
A. リサーチプレビューのため、本番利用は推奨されません。挙動・API・課金が変わる可能性があります。実験的な検証から始めてください。

**Q2. Outcomes の評価ロジックはどこまでカスタマイズできますか？**
A. パブリックベータ時点では、自然言語ベースの判定とスキーマベースの判定が用意されており、独自の判定ロジックも組み込める設計とされています。詳細は公式ドキュメントを参照してください。

**Q3. Multiagent Orchestration を使うと必ず性能が上がりますか？**
A. いいえ。単一エージェントで十分なタスクをマルチ化すると、レイテンシ・コスト・複雑度が悪化します。**役割を分けたほうが明確に有利**な場合に限定して使うのが定石です。

**Q4. Webhooks の配信保証は？**
A. 一般的なベストプラクティスとして「at-least-once（最低 1 回）」を前提に、受信側を冪等に設計してください。署名検証・リトライ・デッドレターキューの設計も必須です。

**Q5. SpaceX 提携で Claude のレスポンスは速くなりますか？**
A. 「速度」よりもまず「上限・スループット」の改善として現れます。重いバッチや並列実行が安定するイメージです。レイテンシそのものは別の最適化軸です。

**Q6. 金融テンプレートは日本の会計基準（J-GAAP）にも対応していますか？**
A. テンプレートは汎用的な業務プロセスを抽象化したもので、地域別の会計基準・規制対応はカスタマイズ前提です。J-GAAP / IFRS / US GAAP の差異は導入時にプロンプト・ナレッジベース側で吸収する必要があります。

**Q7. Cowork とは何ですか？**
A. Anthropic が提供する、Claude を中心とした協働ワークスペース環境です。プラグインとしてエージェント・スキルを追加し、チームで共有しながら業務に組み込めます。

**Q8. Managed Agents と自前のエージェント実装、どちらを選ぶべきですか？**
A. 「ジョブキュー・状態管理・リトライ・スケーリングを自前で持ちたくない」「Anthropic の最新機能（Outcomes / Webhooks / Multiagent）をすぐ使いたい」場合は Managed Agents が有利です。逆に、極端に特殊な実行環境・オフライン要件がある場合は自前実装が必要になります。

## 付録: 用語ミニ辞典

- **Managed Agents**: Anthropic がホストする、本番運用向けエージェント実行基盤
- **Cowork**: Anthropic が提供する協働ワークスペース環境
- **Dreaming**: エージェントがアイドル時間に内省・学習を行うリサーチプレビュー機能
- **Outcomes**: エージェントの成功定義と達成度計測を行う評価フレームワーク
- **Multiagent Orchestration**: 複数エージェントの協調・並列・ハンドオフを管理する仕組み
- **Webhooks**: エージェントの実行イベントを外部システムに通知する仕組み
- **Cookbook**: Anthropic 公式の実装サンプル集
- **Human-in-the-loop（HITL）**: 自動処理の途中で人間の承認・修正を挟む設計
