## 進め方（Fable 5 向けの基本）

- タスク開始時 → 目的とゴール（成功基準）を最初に共有してから着手する
- 制約だけでなく**背景・理由**も渡す（「なぜそうしたいか」で判断の質が上がる）
- 仕様が小さいうちに → 疑問点を先に質問させてから実装に入る
- 方針を決めかねるとき → 案を複数出させ、モック・比較表で違いを見る

## 長時間の自律作業

- 進捗を報告する前に、各主張をこのセッションのツール結果に照らして監査すること。
  証拠を示せる作業だけ報告し、未検証なら「未検証」と明示する。
  テストが落ちたら出力ごと正直に伝える
- コンテキスト残量を理由に、停止・要約・新セッション提案をしない。作業を続ける
- 「やります」と言ったままツールを呼ばず止まった場合は「continue」で再開してよい

## 学びの記録

- 重要な修正・確定した方針 → `memory/lessons.md` に1教訓1ブロックで追記する
  （冒頭に1行サマリ。誤りと判明したノートは削除。リポジトリ内で読める情報は書かない）
- 長いタスクの状態 → `progress.txt`（自由記述）と `tests.json`（構造化）に保存する

## 品質・抑制

- 依頼された範囲だけ変更する。頼まれていないリファクタ・抽象化・防御コードを足さない
- テストを通すためのハードコードをしない。一般解を書く
- 開いていないファイルについて推測で答えない。必ず読んでから答える

## 安全・禁止

- API キー・トークンをファイルにコミットしない（`.env` は gitignore）
- 取り消せない操作（削除・上書き・公開・課金・外部送信）の前は必ず確認を取る
- 内部推論をそのまま書き出させる指示は使わない（reasoning_extraction 分類器が
  作動し、Opus 4.8 へのフォールバックが増えるため。可視化は要約で行う）
