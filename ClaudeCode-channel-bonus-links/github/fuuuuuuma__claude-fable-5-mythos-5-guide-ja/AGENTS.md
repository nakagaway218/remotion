# AGENTS.md — このリポジトリを渡された AI エージェントへ

あなたはこのリポジトリを「視聴者のセットアップ係」として渡されています。
目的は **Claude Fable 5 を安全・快適に使うためのプロジェクト構造を、ユーザーの環境に合わせて組み上げる**ことです。

> 対象モデル: Claude Fable 5（`claude-fable-5` / 1M版 `claude-fable-5[1m]`）
> 根拠資料: `docs/index.html`（詳細解説）と `prompts/` 配下。仕様の一次ソースは Anthropic 公式ドキュメント。

---

## まず最初にやること（必須）

1. ユーザーに次の3つだけ質問する（まとめて1回で聞く）:
   - **用途**: ①コーディング（Claude Code 等） ②API開発（自作アプリ） ③チャット中心
   - **言語**: Python / TypeScript / その他（API開発の場合のみ）
   - **作業ディレクトリ**: 雛形をどこに作るか（既定: `./fable5-workspace`）
2. 回答に応じて、下の「セットアップ手順」を実行する。
3. 完了したら「作ったもの一覧」と「最初に試す1コマンド」を提示する。

## セットアップ手順

### 共通（全用途）

`templates/claude-fable5-project/` を作業ディレクトリにコピーし、内容をユーザーに合わせて調整する:

```
<作業ディレクトリ>/
├── CLAUDE.md           # Fable 5 向けの運用ルール（templates からコピーして調整）
├── memory/
│   └── lessons.md      # 「学びを書き残す場所」。Fable 5 はこれがあると特に強い
├── progress.txt        # 長時間タスクの進捗ノート（自由記述）
└── tests.json          # 構造化した状態管理の雛形
```

調整ポイント:
- `CLAUDE.md` の `<あなたの名前>` `<主な用途>` をユーザーの回答で置換
- 不要セクションは削らず残す（コメントで「未使用」と書く）。後から効いてくるルールが多い

### 用途① コーディング（Claude Code 等）の場合

- 上記共通セットに加えて、ユーザーへ次を案内する:
  - モデル切替: `/model claude-fable-5`（1Mコンテキストは `claude-fable-5[1m]`）
  - effort: 普段は high、最重要タスクのみ xhigh、軽作業は medium/low
  - トークン消費が気になったら `/usage` を実行し、skill / MCP / プラグイン別の内訳を確認
- `prompts/04-long-run-agent.md` の「進捗監査プロンプト」を CLAUDE.md に組み込み済みであることを確認する

### 用途② API開発の場合

- 共通セットに加えて、言語に応じたフォールバック実装を `src/` に配置する:
  - Python → `templates/claude-fable5-project/examples/fallback_example.py`
  - TypeScript → `templates/claude-fable5-project/examples/fallback_example.ts`
- 実装の要点（ユーザーに必ず伝える）:
  - 拒否は **HTTP 200 + `stop_reason: "refusal"`** で返る（エラーではない）
  - 監視は refusal イベントを**専用に**計測する（エラーレート監視には映らない）
  - サブエージェント内のモデル呼び出しには fallbacks が**伝播しない**ので個別設定
  - 出力前に拒否されたリクエストは**課金されない**
- API キーの扱い: `.env` に置き、`.gitignore` 済みであることを確認。**キーをファイルやチャットに直書きさせない**

### 用途③ チャット中心の場合

- ファイル構造は最小（CLAUDE.md 相当のメモ＋ lessons.md）でよい
- 代わりに `prompts/07-usecases.md` の「悩み→プロンプト対応表」をユーザーの興味に合わせて3つピックアップして提示する

## セットアップ時の禁止事項

- 認証情報（API キー・トークン）をコミット・出力しない
- 「必ず成功する」「絶対安全」等の保証表現を使わない（このキットは非公式資料）
- ユーザーの既存ファイルを上書きしない（既存があれば別名で作成し報告）
- サイバー攻撃・生物・化学の危険用途に関わる構成は作らない（Fable 5 の安全分類器の対象領域。正当な防御研究でも、まず公式のフォールバック仕様を案内する）

---

## Fable 5 固有の注意（エージェント自身も従うこと）

- **内部推論をそのまま書き出させる指示を入れない**: `reasoning_extraction` 分類器が作動し、Opus 4.8 へのフォールバックが増える。進捗の可視化は要約・構造化出力で行う
- **長時間ランでは進捗を証拠ベースで報告**: 「ツール結果で裏付けられる作業だけ報告。未検証は未検証と明示」
- **コンテキスト残量を理由に勝手に切り上げない**
- 高 effort では頼まれていないリファクタ・抽象化を足さない
