## 1. そもそも「Antigravity」とは（旧版＝1.0のおさらい）

Google Antigravity の初代（1.0）は、**2025年11月18日**に **Gemini 3** と同時発表された **「エージェントファースト（agent-first）」のIDE** です。一言でいえば「**AIエージェントを主役に据えた統合開発環境**」でした。

### 1.0 の特徴

- **VS Code をベースに大幅改造**したデスクトップアプリ。見た目はおなじみのIDEだが、中身はAIエージェント前提に再設計。
- **2つのビュー（面）** を持つ:
  - **Editor View** … 従来のコードエディタ（人間が編集する画面）
  - **Manager View（Manager Surface）** … 複数のエージェントを**非同期に・並列で**動かす管制画面（**最大5体まで並列**）
- エージェントが **エディタ・ターミナル・ブラウザ** に直接アクセスでき、計画立案からコード実装、**自分のコードの検証**までを自走する。
- **Artifacts（アーティファクト）** … エージェントの作業を検証可能な成果物（タスクリスト・実装計画・スクリーンショット・ブラウザ操作の記録など）として残す仕組み。
- **Knowledge Base（ナレッジベース）** … プロジェクトの文脈をエージェントに与える仕組み。
- **発表時は無料パブリックプレビュー**。対応モデルは Gemini 3.1 Pro / Gemini 3 Flash に加え、Anthropic の Claude（Sonnet / Opus 系）、OpenAI 系オープンモデル GPT-OSS-120B など**マルチモデル**。（※対応モデルの版数はソースにより揺れあり）

> 💡 **押さえどころ**: 1.0 のキャッチは「**コードを書く相棒（assistant）から、自走する開発パートナー（agent）へ**」。この思想を**さらに極端に推し進めた**のが 2.0。

## 2. Antigravity 2.0 とは（I/O 2026 の目玉）

2.0 の本質は **「IDE」から「エージェント開発スイート（プラットフォーム）」への拡張** です。9to5Google は2.0を *"a unified brand for AI coding harnesses fit for the agentic future"*（エージェント時代に向けたAIコーディング基盤の統一ブランド）と表現しています。

ポイントは、Antigravity が **1つのアプリ** から **5つの「サーフェス（接点）」を束ねるプラットフォーム** になったこと。同じエージェント基盤（harness）を、用途に応じて **GUI・ターミナル・コード・API・エンタープライズ** の5つの入り口から使えるようにした、という設計です。

## 3. 5つのサーフェス（2.0の全体像）

| サーフェス | 何をするもの | 向いている用途 |
|---|---|---|
| **① Desktop App** | 複数エージェントを並列に指揮するGUI。2.0の「ホーム」 | ビジュアルでのワークフロー管理 |
| **② CLI（`agy`）** | ターミナルからエージェントを起動する軽量ランタイム | スクリプト・CI/CD・自動化 |
| **③ SDK** | Gemini最適化のエージェントを自作するための開発キット | 独自エージェントの構築 |
| **④ Managed Agents API** | API1回呼ぶだけでエージェントを丸ごと実行 | サーバーレスなエージェント実行 |
| **⑤ Enterprise Platform** | Google Cloud と直結。監査ログ等のガバナンス対応 | 統制が必要なチーム・企業 |

### ① Desktop App（デスクトップアプリ）

「**エージェント操作の中心拠点（central home for agent interaction）**」と位置づけられ、**複数のエージェントを束ねてタスクを並列実行**する。新機能は以下:

- **ダイナミック・サブエージェント（Dynamic Subagents）** … 親エージェントが**子エージェントを動的に生成**し、仕事を分割して並列処理。例:「全マイクロサービスの認証フローを監査して」と頼むと、**サービスごとに1体ずつスコープを切った子エージェントのツリー**に分解し、同時並行で走らせる（※例示はApidogのガイド）。
- **スケジュールタスク（Scheduled Tasks）** … cron のように**バックグラウンドで定期実行**。夜間の依存関係アップデート、週次のセキュリティスキャンなど。
- **音声コマンド（Voice Commands）** … 音声でコードを口述、差分を尋ねる、テスト実行を声で指示。（※単一ソース寄り）
- **エコシステム連携** … **Google AI Studio / Android / Firebase** と統合。AI Studio のプロジェクトをローカル開発へ**エクスポート**する機能も。

### ② CLI（`agy`）

- ターミナルから **GUIなしで即座にエージェントを生成・実行**できる軽量ツール。
- **旧 Gemini CLI を置き換える**位置づけ（後述の移行参照）。
- ランタイム依存のない自己完結バイナリ（Go製と報じられる）。デスクトップアプリと双方向同期。

### ③ SDK

- Google 製品を支えるのと**同じエージェント基盤（agent harness）にプログラムからアクセス**できる。
- **Gemini モデルに最適化**されており、**低レイテンシ・低コスト**が売り。
- **MCP（Model Context Protocol）** に対応。独自のエージェント挙動を定義し、**自社インフラ／Google Cloud のどちらでもホスト可能**。

### ④ Managed Agents（Gemini API の新機能）

- **API を1回呼ぶだけ** で、エージェントが「**推論し、ツールを使い、隔離されたLinux環境でコードを実行**」する。
- 自分でループ（エージェントの制御）を管理する必要がなく、「**ゴールを宣言し、許可するツールを並べれば、あとはGoogleが代わりに走らせる**」サーバーレス方式。
- 環境は**永続的かつ隔離**され、複数ターンにまたがって**再開（resume）可能**。Markdownファイルでカスタム指示やスキルを与えられる。

### ⑤ Enterprise Agent Platform

- Google Cloud 顧客が **Antigravity を自社の Cloud プロジェクトに直結**できる。
- 監査証跡（audit trail）などガバナンス重視のチーム向け。AI Studio で**カスタムエージェントのテンプレート**も提供。

## 4. 旧版（1.0）からの変化 — ここが一番のキモ

動画で「**Antigravity からの変化**」を語るなら、ここが核心です。

### 変化①：コードエディタが「主役」から外れた（最重要）

1.0 は VS Code ベースで、画面の中心に**コードエディタ**があった。2.0 は **「VS Code 上に作られたものではない、独立したエージェント管理システム」** へ。BuildFastWithAI は *"Antigravity 2.0 is not built on VS Code — it is a standalone agent management system that can optionally be used alongside an IDE."*（VS Code製ではなく、IDEと併用も選べる独立したエージェント管理システム）と説明している。

→ つまり **「人間がコードを書く場所」だったものが、「AIエージェントを指揮する管制室」になった**。Augment Code はこの思想を **"You are the orchestrator, not the developer."**（あなたは開発者ではなく、指揮者だ）と要約している。

### 変化②：1体 → 複数を「動的」に並列

1.0 も最大5体の並列はできたが、2.0 は **親が子（サブエージェント）を動的に生み、ツリー状に分岐させて並列処理**できるようになった。「速度を掛け算する」方向の進化。

### 変化③：1アプリ → 5サーフェスのスイート化

前述の通り、GUI単体から **CLI・SDK・Managed API・Enterprise** を含むプラットフォームへ。

### 変化④：スケジュール実行・音声・エコシステム連携の追加

バックグラウンド定期実行、音声操作、Firebase / Android / AI Studio 連携が新規追加。

### 変化⑤：モデルとスピード

2.0 は **Gemini 3.5 Flash** をデフォルトに採用。このモデルは **Antigravity 自身を使って共同開発**されたとされ、**Antigravity 向けに最適化された Gemini 3.5 Flash は、同品質を保ったまま汎用的なAPIループに比べ約12倍速い**、というのが Google 公式キーノートの主張（※比較対象は「汎用APIループ」かつ「同品質前提」の条件付き）。引き続き Gemini 3 Pro、Anthropic の Claude（Sonnet / Opus）、GPT-OSS なども選べるマルチモデル。

## 5. 「話題になっていること」（2026年5月時点）

### 🔥 話題1：ローンチ炎上 — 「コードエディタはどこ行った？」

2.0 で最も拡散したのは、**ポジティブな新機能より「炎上」** でした。

- **2026年5月19日のローンチ日**、自動アップデートが既存ユーザーに配信され、**内蔵コードエディタが消失**。**保存していた設定が初期化**され、進行中のプロジェクトが**使えなくなった**人が続出。
- Reddit や Google公式の開発者フォーラムは「**Where is the code editor?（コードエディタはどこ？）**」という同じ叫びで埋まった。
- **大量のアンインストール**が発生し、従来の代替ツールへ出戻る開発者も。「**非エンジニアが本番にコードを出した感じ（reeks of non-technical people shipping code to production）**」と痛烈に評する声も出た。
- レビュー記事の見出しにも「**My experience with Antigravity 2.0 (it's bad!)**」「**Developers Furious**」「**Broke Thousands of Developer Setups Overnight**」といった強い表現が並んだ。

### ⚖️ 話題2：それでも「パラダイムシフト」と評価する声

一方で、XDA Developers・DataCamp・Augment Code などの**腰を据えたレビュー**は、2.0のアーキテクチャを **「乗り越える価値のある本物のパラダイムシフト」** と捉えている。論点を整理すると:

> **「製品ビジョンは本物。ただしローンチの実行（execution）が下手だった」** — この2つは同時に真。

動画では「炎上したけど、思想自体は次の時代を先取りしている」という**両面**を見せると説得力が出ます。

### 📊 話題3：ベンチマークとキーノートのデモ

- **MCP Atlas スコア 83.6%**（マルチステップのツール連携の強さを示す指標。競合を上回るとの主張。複数ソースで確認）。
- **OSのコアをゼロから構築 → その上で Doom クローンを動かす**実証ケースが示された。**約93のサブエージェントを並列で動かし、約12時間・1.5万件超のリクエストで、コストは1,000ドル未満**と複数ソースが報道（※キーノートのライブ実演ではなく事前実行の実証。トークン数など一部指標はソースにより差あり）。

> ⚠️ ベンチ数値・デモのコスト・「12倍速」などの**性能系の数字は、計測条件や比較の前提が揃っていない**ものが多いです。動画で使う場合は「公式発表／報道によれば」と前置きするのが安全です。

## 6. 実際にどう使う？（実践イメージ）

> 以下のコマンド・コード例は**各ガイド（Apidog / BuildFastWithAI 等）が紹介している例**です。**公式の正式仕様とは細部が異なる可能性**があるため、実行前に公式ドキュメントでの確認を推奨します。

### 6-1. インストール（報じられている手順）

```bash
# macOS / Linux
curl -fsSL https://antigravity.google/cli/install.sh | bash

# Windows (PowerShell)
irm https://antigravity.google/cli/install.ps1 | iex
```

初回起動時にブラウザの OAuth で認証。移行期間中は **Gemini CLI と `agy` が共存**可能。

### 6-2. プロジェクト設定ファイル

- ルートに **`AGENTS.md`** を置き、平易な言葉でエージェントへの指示を書く（**旧 `GEMINI.md` の後継**）。
- スキルは **`.gemini/skills/` → `.agents/skills/`** へ移動。

### 6-3. CLI でエージェントを走らせる（例）

```bash
agy agent run "rate-limit ミドルウェアをリファクタして" \
  --repo ./services/api \
  --model gemini-3.5-flash
```

### 6-4. SDK で独自エージェントを作る（例：Python）

```python
from antigravity import Agent, Tool

agent = Agent(
    model="gemini-3.5-flash",
    tools=[Tool.shell, Tool.code_edit, Tool.web_search],
    system="あなたはバックエンドのコードレビュアー。インデックスのないSQLを含むPRはブロックせよ。",
)
result = agent.run("review PR #421")
print(result.artifacts)
```

### 6-5. サブエージェントの使いどころ

「**全マイクロサービスの認証フローを監査して**」のような**横断タスク**を投げると、サービス単位の子エージェントに自動分割して並列処理。**広く浅く同時に**こなす作業に強い。

### 6-6. スケジュールタスク

- 夜間：依存パッケージの自動アップデート
- 週次：セキュリティスキャン
- 定期：ログ要約・レポート生成

### 6-7. Gemini CLI からの移行チェックリスト（締切 2026/6/18）

1. `agy` バイナリをインストール
2. 同じ Google アカウントで認証
3. `agy plugin import gemini`（プラグイン移行）
4. `GEMINI.md` → `AGENTS.md` にリネーム
5. `.gemini/skills/` → `.agents/skills/` に移動
6. `agy doctor` で検証

> 典型的な構成なら**10分以内**で移行完了と報じられている。

## 9. 初心者向け：Antigravityで「こんなことができる」

> 💡 むずかしい用語ぬきで「**何ができて、どう頼むのか**」をイメージできるようにまとめます。コードが分からなくてもOK。
> ⚠️ 下のコマンド記法は §6 同様あくまで「例」ですが、**プロンプト（AIに頼む言葉）はそのまま流用OK**。

### 9-1. ひとことで言うと？

- Antigravity は「コードを書くのを手伝うAI」ではなく、**日本語でお願いすると、AIが代わりに作って・直してくれる**道具。
- あなたの役割は"自分で手を動かす人"から、**指示を出して仕上がりを確認する"監督"**へ。
- しかも助手は1人じゃない。**「これとこれ、同時にやっといて」とまとめて頼める**のが 2.0 の目玉。

> 🎬 **イメージ**: 自分で料理を作るのではなく、**「パスタとサラダ、同時にお願い」とシェフに頼む**感覚。出てきたお皿を味見して、気になればもう一度頼むだけ。

### 9-2. こんな場面で使える（あなたの悩み → こう頼むだけ）

| こんな時 | AIにこう頼む |
|---|---|
| アプリのアイデアはあるが作り方が分からない | 「○○できる簡単なアプリの土台を作って」 |
| エラーが出て動かない／原因が分からない | 「このエラーの原因を調べて直して」 |
| コードの意味が分からない（勉強中） | 「このファイルが何をしているか初心者向けに説明して」 |
| 動作チェックが面倒 | 「ちゃんと動くか確かめる仕組みを足して、結果を見せて」 |
| 毎週くりかえす手作業をなくしたい | 「毎晩○○を自動でやっておいて」 |

→ 「自分で全部書く」のではなく「**お願いして、確認する**」。ここが一番のイメージの転換点です。

### 9-3. 今すぐ試せる、最初の3ステップ

1. **入れる** — アプリをダウンロード（or `agy` を入れる：§6-1）
2. **日本語で1つ頼む** — 下のプロンプトを入力欄にコピペするだけ
3. **確認する** — 出てきた結果を見て、OKならそのまま／直したければ「ここをこう変えて」と返すだけ

### 9-4. コピペで使える、やさしいプロンプト例

> アプリのチャット欄に貼るだけ（CLIの人は `agy agent run "～"` で囲みます）。

**① まず説明してもらう（こわくない第一歩）**
```
このプロジェクトが何をするものか、プログラミング初心者にも分かるように説明して
```

**② 小さく作ってもらう**
```
ボタンを押すと「こんにちは！」と表示される、シンプルなWebページを作って
```

**③ 直してもらう（原因もやさしく教えてもらう）**
```
このエラーの原因を調べて直して。なぜ起きたのかも、初心者に分かるように教えて
```

**④ 任せて、結果を見せてもらう**
```
このプログラムがちゃんと動くか確かめるテストを足して、実行した結果を見せて
```

→ どれも「**やってもらう → 出てきたものを見る**」の流れ。気に入らなければ言葉で直せるのがポイントです。

### 9-5. 慣れてきたら：もう一歩進んだ使い方

ここから先は開発者向け（最初は読み飛ばしてOK）:

- **複数を同時に**: 「すべてのファイルをまとめて点検して」のような横断作業を、サブエージェントが**手分けして並列**でこなす
- **定期的に自動で**: 「毎晩、古くなった部品を最新に更新して」など、放置で回る定期作業（Scheduled Tasks）
- **自分専用ルール**: `AGENTS.md` に「報告は日本語で」などを書くと、毎回指示しなくて済む（§6 参照）
- **コードに組み込む**: SDK で自作エージェントを常駐させる（上級者向け：§6-4）
- **裏技**: 速さ重視は Gemini 3.5 Flash・正確さ重視は Claude 系と**モデルを使い分け**／結果は Artifact で裏取り／残量（`/usage`）は5時間ごとに回復する前提で計画
