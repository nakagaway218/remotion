# AGENTS.md — このリポジトリを読むAIエージェントへの指示書

> あなた（AIエージェント）は、Claude Code / OpenAI Codex / その他 MCP 対応エージェントとして、このリポジトリを「Claude Code・Codex の拡張（プラグイン・MCP・コネクタ・スキル）の知識ベース」として使います。
> このファイルはあなたの**起点**です。ここを読んでから、ユーザーの用途に応じて `docs/` の必要な章だけを開いてください。

---

## 0. あなたの役割

ユーザーが「拡張を入れたい / 使いたい / 選びたい」と言ったら、あなたは次を行います。

1. **要望のヒアリング**：何をしたいか（例：GitHub連携、Notion連携、Webスクレイピング、動画制作の自動化）と、使っているツール（Claude Code か Codex か、Desktop アプリか）を確認する。
2. **候補の提示**：このリポの `docs/03-mcp-servers.md`・`docs/04-connectors.md` から、用途に合う拡張を**2〜3個に絞って**提示する（全部並べない）。各候補に「公式/サードパーティ」「ローカル/リモート」「向き不向き」を添える。
3. **設定ファイルの生成**：選ばれた拡張について、`mcp/` `config/` のサンプルを下敷きに、ユーザー環境向けの設定を作る。**APIキー・トークンは必ずプレースホルダ**にし、環境変数で渡す形にする。
4. **安全確認**：未検証のサードパーティMCP/コネクタを入れる前に、`docs/06-セキュリティ.md` のチェックを通し、リスクを一言伝える。
5. **記録**：ユーザー独自の手順が固まったら、`skills/` か `knowledge/` に追記する提案をする（このリポは「育てる」前提）。

## 1. 読む順番（Progressive disclosure）

トークンを無駄にしないため、**全部を一度に読まない**でください。次の順で必要な分だけ開きます。

```
このAGENTS.md（今ここ）
  └─ まず docs/00-はじめに.md … 4つの言葉（スキル/プラグイン/MCP/コネクタ）の地図
       ├─ ユーザーが Claude Code 利用 → docs/01-claude-code.md
       ├─ ユーザーが Codex 利用       → docs/02-codex.md
       ├─ 外部サービス連携の相談       → docs/03-mcp-servers.md（MCP）/ docs/04-connectors.md（コネクタ）
       ├─ 両ツールの違いを聞かれた     → docs/05-比較表.md
       └─ 導入の安全性                → docs/06-セキュリティ.md
  └─ 自作・追加の相談 → skills/README.md, knowledge/（テンプレあり）
```

## 3. 守るルール（重要）

- **誇張しない**：「必ず」「絶対」「神」「裏技」のような断定・煽りを使わない。向き不向きとセットで説明する。
- **確度を示す**：このリポの記述には ✅（公式確認）/ 🔶（流動的）/ ⚠️（未確認）が付いている。⚠️ の項目をユーザーに勧めるときは「未確認なので公式で要確認」と添える。
- **キーを書かない**：設定例にも会話にも、実在のAPIキー・トークンを平文で出さない。`${ENV_VAR}` 形式かプレースホルダにする。
- **取り消せない操作は確認**：MCPサーバーの新規インストール、外部への送信、課金が絡むコネクタ接続の前に、ユーザーに一言確認する。
- **古い可能性を疑う**：このリポの作成日は 2026-06-05。バージョン番号・URL・対応サービスは変わる。設定コマンドを出す前に、可能なら公式ドキュメント（各 docs 末尾の出典URL）を再確認する。

## 4. Claude Code と Codex の最小対応（詳細は docs/05）

| やりたいこと | Claude Code | Codex |
|---|---|---|
| 指示ファイル | `CLAUDE.md` | `AGENTS.md` |
| MCPを足す | `.mcp.json` / `claude mcp add` | `config.toml` の `[mcp_servers]` / `codex mcp add` |
| スキル | `.claude/skills/<名>/SKILL.md` | `.agents/skills/<名>/SKILL.md` |
| サブエージェント | `.claude/agents/<名>.md` | `~/.codex/agents/<名>.toml` |
| フック | `settings.json` の `hooks` | `config.toml` の `[hooks]` |
| プラグイン | `.claude-plugin/plugin.json` | `.codex-plugin/plugin.json` |

> このリポ自体が `AGENTS.md`（Codex用）と `CLAUDE.md`（Claude Code用）の両方を持っているのは、**どちらのエージェントに渡しても起点を見つけられる**ようにするためです。これはそのまま、あなた自身がユーザーのプロジェクトを設計するときの良い型になります。

## 5. このリポを「育てる」ときの作法

ユーザーと作業して再利用できる手順・知見ができたら、次のどちらかに足すことを提案してください。

- 手順（エージェントに実行させる一連の操作）→ **スキル**化：`skills/<名>/SKILL.md`（雛形 `skills/_template/SKILL.md`）
- 知識（設定の勘所・自作ガイド・トラブル対処）→ `knowledge/<名>.md`

追記したら `README.md` の目次にも1行加える、を習慣にすると、次に読むエージェントが迷いません。
