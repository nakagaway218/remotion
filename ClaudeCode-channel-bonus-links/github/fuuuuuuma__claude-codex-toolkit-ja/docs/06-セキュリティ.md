# 06. セキュリティ — MCP / コネクタを安全に入れる

> 拡張は便利な反面、「外部のコードに手の内を見せる」行為でもあります。ここは導入前に必ず通したいチェックです。難しくありません。要点は「信頼できるものだけ・キーは隠す・実行は確認」。2026-06時点。

確度マーク：✅ 公式/一次確認 ／ 🔶 流動的 ／ ⚠️ 二次情報

---

## 1. なぜ注意が必要か（一言で）

MCPサーバーやコネクタは、ツールの**説明文や取得したデータがエージェントのコンテキストに入ります**。ここが汚染されると、エージェントが意図しないツールを呼んだり、データを外に流したりする経路になり得ます。これを **プロンプトインジェクション / ツールポイズニング（tool poisoning）** と呼びます。🔶

実例（報告ベース）：
- 2025年の調査で、調べた1,899のMCPサーバーのうち約5.5%にツールポイズニングの脆弱性が見つかったという報告。⚠️（二次情報・出典末尾）
- 2025年11月、あるメッセージ連携MCPで、ツール説明に隠した指示でメッセージ履歴を攻撃者に流出させ得る脆弱性が報告。⚠️

> 数値・事例は二次情報です。重要なのは「**こういうリスクが構造的に存在する**」という理解で、特定の数字ではありません。

---

## 2. 導入前チェックリスト（これだけ守る）

エージェントがユーザーに新しいMCP/コネクタを勧める時、次を確認させてください。

- [ ] **提供元は信頼できるか**：公式（ベンダー自身）か、Anthropic検証済みディレクトリか。素性不明の個人repoは慎重に。✅
- [ ] **ソースを見られるか**：OSSなら一度コードを確認。特に「ツール説明文」に不審な指示が埋まっていないか。🔶
- [ ] **要求する権限は最小か**：read だけで足りるのに write/delete を要求していないか。
- [ ] **キーの渡し方**：APIキー・トークンを**設定ファイルに直書きしない**。環境変数（`${ENV_VAR}`）で渡す。✅
- [ ] **実行系の操作**：削除・送信・投稿・課金が絡むツールは、エージェントに任せきりにせず人間が実行前確認。✅
- [ ] **スコープ**：可能なら project スコープより限定的に。Claude Code は project-scoped `.mcp.json` を**初回利用時に承認プロンプト**で止める。✅

---

## 3. キーを漏らさない（最重要・具体策）✅

- 設定ファイル（`.mcp.json` / `config.toml` / `settings.json`）に**実キーを書かない**。`${GITHUB_PAT}` のように環境変数参照にする。
- `.env` や `credentials.*` は **`.gitignore` 必須**。誤ってコミットしない。
- このリポのサンプルはすべて `YOUR_..._KEY` 等の**プレースホルダ**です。そのまま使わず置き換えてください。
- 公開リポジトリにMCP設定を入れる場合、キーが含まれていないか push 前に確認。

`.gitignore` の最低ライン：

```gitignore
.env
.env.*
*credentials*
*.key
.mcp.local.json
```

---

## 4. コネクタ特有の注意 ✅

- カスタムコネクタは「Anthropic が検証していない任意サービス」に繋げます。公式も警告しています。**URL の素性**を確認。
- リモートコネクタは **Anthropic のクラウドからサーバーに接続**します。社内限定データを扱う場合は、到達範囲・ログ・保存先を提供元の規約で確認。
- 組織利用では、管理者が **read-only 制限**や**プライベートプロジェクト限定**を設定できます。チームではこれを活用。
- 「同期コンテンツを含むチャットは共有不可」になる点も理解しておく。

---

## 5. 対策の型（運用でやること）🔶

- **ツール説明の変更を監視**：信頼したサーバーでも、後からツール説明が書き換わる「rug pull」があり得る。アップデート時は再確認。
- **監査ログ**：何のツールがいつ呼ばれたかを残す（可能な範囲で）。
- **OAuthスコープの最小化**：必要な権限だけに絞る。
- **ゲートウェイ/承認**：重要操作は人間の承認を挟む（Claude Code/Codex の approval 設定）。

---

## 6. このリポを使うエージェントへの指示（再掲）

- ⚠️ マークの付いた拡張をユーザーに勧める時は、「未確認なので公式で要確認」と必ず添える。
- 新規MCPの**インストール・外部送信・課金**の前に、ユーザーに一言確認する。
- 設定例にも会話にも、実在のキーを平文で出さない。
