# 00. はじめに — プラグイン・MCP・コネクタ・スキルとは

> ここは「言葉の地図」です。専門用語に入る前に、まず日常語で4つの言葉を区別します。これさえ掴めば、後の章は迷いません。

---

## まず一番大事な区別

AIエージェント（Claude Code や Codex）の拡張は、ざっくり**2つの目的**に分かれます。

1. **エージェントの「やり方」を増やす** … スキル / コマンド / サブエージェント / フック
2. **エージェントの「手の届く先」を増やす** … MCP サーバー / コネクタ

そして、これらを**まとめて配るための箱**が **プラグイン**です。

比喩でいうと——

- あなたは**料理人（エージェント）**。
- **スキル**は「レシピ集」。必要な時だけ開く手順書。
- **MCP サーバー / コネクタ**は「冷蔵庫や宅配サービスへの扉」。外から食材（データ）を取り、外で行動（投稿・更新）する。
- **プラグイン**は「レシピも扉の鍵もまとめて入った道具箱」。人に丸ごと渡せる。

---

## 4つの言葉（やさしい定義つき）

### 1. スキル（Skill）✅

エージェントへの**手順書**です。`SKILL.md` というファイル1枚（＋必要なら補助ファイル）でできています。

- 「いつ使うか」を書いた説明文がついていて、エージェントは**必要な時だけ中身を読み込みます**（これを progressive disclosure ＝段階的開示と呼びます）。だからたくさん入れても普段は邪魔になりません。
- 例：「この手順でnote記事を整形する」「この順番でテストを走らせる」。
- 悩み別の例：
  - 「毎回同じ説明を書くのが面倒」→ その手順をスキルにすれば、一言で呼べる。
  - 「チームで作業手順を揃えたい」→ スキルを共有すれば全員同じ動きになる。

### 2. プラグイン（Plugin）✅

スキル・コマンド・サブエージェント・フック・MCP設定などを**まとめて1つにした配布パッケージ**です。

- 「マーケットプレイス（カタログ）」から探して入れます。アプリストアにストアを登録してからアプリを入れる、のと同じ2段階です。
- 例：「GitHub連携プラグインを入れたら、GitHub用のコマンドとMCP設定が一式そろう」。
- 悩み別の例：
  - 「便利な拡張をいちいち手で設定したくない」→ プラグインなら一括で入る。

### 3. MCP サーバー（MCP server）✅

外部サービス（GitHub・Notion・Slack・データベースなど）に繋ぐための**共通規格のアダプタ**です。MCP は **Model Context Protocol** の略で、Anthropic が2024年11月に公開したオープン標準です（出典は末尾）。

- USB のように「規格が同じなら、どのエージェントからでも同じサーバーを挿せる」のが利点。Claude Code でも Codex でも同じMCPサーバーが使えます。
- **ローカル型**（自分のPCで動く）と**リモート型**（インターネットの向こうで動く）があります。
- 例：「Notion の MCP サーバーを挿すと、エージェントが Notion のページを読んだり作ったりできる」。

### 4. コネクタ（Connector）✅

Claude のアプリ（claude.ai / Claude Desktop / Cowork / モバイル）から、MCP サーバーを**ログインだけで使える形にしたもの**です。

- 中身は MCP サーバーですが、ユーザーから見ると「アプリを繋ぐボタン」。技術用語を知らなくても使えるのがコネクタの役割です。
- 「Google Drive を繋ぐ」「Slack を繋ぐ」のように、OAuth（＝サービスにログインして許可する仕組み）でつなぎます。

## 4つの「層」マップ（全体像）

上から「人が触る体験」、下に行くほど「技術の土台」です。

```
┌─────────────────────────────────────────────┐
│  コネクタ（Connector）                        │  ← claude.ai / Desktop で「ログインして繋ぐ」体験
│   例: Google Drive, Slack, Notion …          │
├─────────────────────────────────────────────┤
│  MCP サーバー（local / remote）               │  ← コネクタやエージェントの実体
│   GitHub / Figma / Postgres / Playwright …   │
├─────────────────────────────────────────────┤
│  MCP（Model Context Protocol）= 共通規格      │  ← 土台のプロトコル
└─────────────────────────────────────────────┘

       〔別系統・配布の仕組み〕
   スキル / コマンド / サブエージェント / フック
        └──まとめて──▶ プラグイン ──配る──▶ マーケットプレイス
```

ポイント：
- **コネクタとMCPサーバーは別物ではなく「層の違い」**。コネクタの中身はMCPサーバーです。✅
- **プラグインはMCPとは別系統の「配布の箱」**。ただし箱の中にMCP設定を同梱できるので、両者は重なります。✅

---

## どれを選べばいい？（最短の指針）

- とにかく外部サービス（Notion/Slack/Drive）と繋ぎたい、難しいことはしたくない → **コネクタ（リモートMCP）**。ログインだけ。
- コーディング用のツール（GitHub・ブラウザ操作・最新ドキュメント参照）を足したい → **MCP サーバー**を `docs/03-mcp-servers.md` から選ぶ。
- 便利な拡張を一括で入れたい → **プラグイン**を `docs/01-claude-code.md` / `docs/02-codex.md` のマーケットプレイスから。
- 自分専用の手順を覚えさせたい → **スキル**を作る（`skills/_template/SKILL.md`）。
- 自社API・独自ツールに繋ぎたい → **MCP サーバーを自作**（`knowledge/` のテンプレ）。

次の章からは、Claude Code 編・Codex 編・MCP一覧・コネクタ一覧、と具体に入ります。
