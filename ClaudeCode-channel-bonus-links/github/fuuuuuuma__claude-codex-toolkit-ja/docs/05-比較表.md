# 05. Claude Code ↔ Codex 対応表・拡張の「層」マップ

> Claude Code と OpenAI Codex は、拡張の**考え方がほぼ同じ**で、置き場所とファイル形式（Markdown vs TOML）が違うだけ、という見方ができます。この章は「片方を知っていればもう片方も使える」ための対応表です。2026-06時点。

確度マーク：✅ 公式確認 ／ 🔶 流動的 ／ ⚠️ 未確認

---

## 1. 概念の対応表 ✅

| やりたいこと | Claude Code | OpenAI Codex |
|---|---|---|
| エージェントへの永続指示 | `CLAUDE.md` | `AGENTS.md`（`AGENTS.override.md` で上書き、`~/.codex/AGENTS.md` がグローバル） |
| 指示の階層マージ | ディレクトリ階層で読む | Gitルート→CWDへ下りながら連結（近いほど優先） |
| カスタムコマンド | `.claude/commands/<名>.md` | `~/.codex/prompts/<名>.md`（🔶 非推奨化・後継はスキル） |
| スキル | `.claude/skills/<名>/SKILL.md` ／ `~/.claude/skills/` | `.agents/skills/<名>/SKILL.md` ／ `$HOME/.agents/skills/` ／ `/etc/codex/skills` |
| サブエージェント | `.claude/agents/<名>.md`（Markdown） | `~/.codex/agents/<名>.toml` ／ `.codex/agents/`（TOML） |
| 並列エージェント設定 | （セッション/設定で制御） | `[agents]` テーブル（`max_threads` 等）＋ `multi_agent` トグル |
| フック | `settings.json` の `hooks`（JSON） | `config.toml` の `[hooks]` ／ `hooks.json` |
| MCP サーバー | `.mcp.json` ／ `claude mcp add` | `config.toml` の `[mcp_servers.<id>]` ／ `codex mcp add` |
| プラグイン | `.claude-plugin/plugin.json` | `.codex-plugin/plugin.json` |
| マーケットプレイス | `/plugin marketplace add owner/repo` | `codex plugin marketplace add owner/repo` |
| 設定レイヤー | `settings.json`（個人/プロジェクト/local/組織） | `config.toml` ＋ `--profile <名>`（`~/.codex/<名>.config.toml`） |
| 全体設定の形式 | JSON | TOML |

出典：Claude Code は code.claude.com/docs、Codex は developers.openai.com/codex（各 docs 末尾参照）。✅

## 2. 「層」マップ（両ツール共通）

```
┌──────────── やり方を増やす（配布の箱＝プラグイン） ────────────┐
│  スキル / コマンド / サブエージェント / フック                  │
│       └─ Claude Code: .claude/ 配下（Markdown/JSON）            │
│       └─ Codex:       .agents/ , ~/.codex/ 配下（Markdown/TOML） │
└────────────────────────────────────────────────────────────────┘
┌──────────── 手の届く先を増やす ────────────┐
│  MCP サーバー（規格共通・両ツールで同じものが使える）           │
│       └─ ローカル(stdio) / リモート(Streamable HTTP, OAuth)     │
│  コネクタ（Claudeアプリでの体験。中身はMCP）                    │
└────────────────────────────────────────────────────────────────┘
        土台：MCP（Model Context Protocol）= オープン標準
```

**重要な実用ポイント**：
- **MCPサーバーは規格が共通**なので、`docs/03-mcp-servers.md` で選んだサーバーは Claude Code でも Codex でも使えます。置き換えるのは「設定ファイルの書き方」だけ。✅
- **スキルの `SKILL.md` は共通形式**（frontmatter に `name` / `description`、本文 Markdown）。`.claude/skills/` と `.agents/skills/` の両方に置けば共用できます。✅

---

## 3. どちらを選ぶ？（ざっくり指針）

これは優劣ではなく「手元の環境・好み」で決めます。誇張のない範囲で：

- すでに Claude（claude.ai / Desktop）でコネクタを使っている、Anthropicモデル中心 → **Claude Code** が地続き。
- OpenAI のモデル・エコシステムを中心に使う、TOML設定が好み → **Codex**。
- **両方使う**なら、本リポのように `AGENTS.md` と `CLAUDE.md` を両方置き、MCPサーバーとスキルを共用するのが無駄がありません。✅

> どちらも 2026年時点で「スキル・MCP・プラグイン・フック」が揃っており、機能の方向性は近いです。細かな最新差分（モデル名・新機能）は各公式で確認してください。

---

## 4. 移植チェックリスト（Claude Code → Codex に持っていく時）

1. `CLAUDE.md` の指示 → `AGENTS.md` にコピー（または `project_doc_fallback_filenames` に `CLAUDE.md` を追加 🔶）。
2. `.mcp.json` のサーバー → `config.toml` の `[mcp_servers.<id>]` に変換（[mcp/](../mcp/) のサンプル参照）。
3. `.claude/skills/` の `SKILL.md` → `.agents/skills/` にコピー。
4. `settings.json` の `hooks` → `config.toml` の `[hooks]` に変換（command型は概ね移植可、それ以外は要確認 🔶）。
5. サブエージェント（Markdown）→ Codex は TOML スキーマ（`name`/`description`/`developer_instructions`）に書き直し。
