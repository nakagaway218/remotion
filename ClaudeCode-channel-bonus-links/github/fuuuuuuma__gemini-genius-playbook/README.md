## ① Project Genie — テキストから「歩ける3D世界」を生成（Genie 3）

### 1-1. Project Genie とは何か（30秒で）

Project Genie は **Google DeepMind の世界モデル「Genie 3」を一般公開した Google Labs の実験プロジェクト**。
2026年1月29日に **Google AI Ultra 加入者（米国18+）向け** にローンチ、テキストプロンプトから**インタラクティブな3D世界**を生成し、実際に WASD で**歩き回れる**ツールです。

| 項目 | スペック |
|---|---|
| 解像度 | 720p |
| フレームレート | 20〜24fps（リアルタイム対話） |
| 操作 | WASD で移動／矢印キーでカメラ／スペースで上昇 |
| 視点 | 一人称 / 三人称 切替 |
| 初期地点 | テキスト or Google Maps Street View から派生 / 「Roll the dice」でランダム |
| 一貫性 | 一度生成した世界は **再訪時もディテールを記憶** |
| アクセス | [labs.google/fx/projectgenie](https://labs.google/fx/projectgenie)（Ultraサインイン） |

> **未確認**：日本リージョン提供時期、動画書き出し機能の有無、商用利用可否。撮影前に最新の公式ヘルプで再確認推奨。

「動画を**観る**」のではなく「世界に**居る**」のが Veo / Flow との決定的な違い。撮影台本では以下3つが刺さります。

1. **絵コンテ前のロケハン代替** — 実在しない／行けない場所を歩いて、構図・光線・空間感を確かめる
2. **世界観リファレンスの収集** — 気に入った位置でスクショ → ムードボード化 → スタッフ共有
3. **動画の冒頭フック** — 「テキスト3行で歩ける世界を作る」実演自体が強烈な掴み

### 1-2. 裏技ポイント 5選

#### 裏技① 「ロケハン → 実写撮影」の二段構え
生成した世界を歩いて気に入った構図・光線をスクショ → **実写撮影の絵コンテに転用**。
ロケ地に行く前に「世界を歩いて」アイデアを固められる。本物より早く、自由度が高い。

#### 裏技② Street View を「初期地点」として使う
完全テキストではなく **Maps Street View の実在地点から派生** させると、**既視感 + AIの飛躍** のハイブリッドが作れる。
例：「渋谷スクランブル交差点を中世風に」「自分の地元の駅を50年後に」など、視聴者の親近感が桁違いに上がる。

#### 裏技③ プロンプトに「**時間軸の物語**」を含める
「ここで5分前に何があったか」「これから何が起きるか」を書くと、世界に**物語の余韻**が宿る。
散らかった机／燃え跡／足跡／空のグラス──こういう「気配」が背景の説得力を作る。

#### 裏技④ 「**目線の高さ**」で意味が変わる
プレイヤー視点で動くため、視点の高さを指定するだけで世界の意味合いが激変。
- 「子供の目線で」→ 全てが巨大化、ノスタルジー演出に
- 「猫の高さで」→ 隠れ家感
- 「鳥の視点で」→ 神視点ドキュメンタリー風

#### 裏技⑤ 動画素材化は **画面録画 → 編集ソフト** が現実解
公式の動画書き出しは限定的（未確認）。**OBS / QuickTime / Screen Studio で画面録画 → Premiere に取り込み**が現実的。
30秒の歩き回りでも、編集で2倍速＋カット繋ぎするとB-roll素材として強い。

## ② NanoBanana / Gemini Omni — 日本語が驚くほど通る画像生成

### 2-1. NanoBanana とは（30秒で）

NanoBanana は Google の画像編集モデルの内部コードネームとして広まった呼び名で、現在は **Gemini の画像生成・編集機能** として一般公開されています（公式名：Gemini Image 等。本資料では通称 NanoBanana で統一）。
特徴は3つ。
1. **日本語プロンプトの理解度が圧倒的に高い**（漢字混じりの長文OK）
2. **画像中の文字レンダリングが綺麗**（タイポグラフィ・看板・吹き出し）
3. **対話的に編集できる**（「この部分だけ赤に」が通る）

Imagen 4 / Veo 3 と同じく Gemini 2.5 系の理解力を共有しているため、「Midjourneyではこの表現がプロンプトに乗らない」という壁を、自然な日本語で越えられます。

### 2-2. 裏技ポイント 5選

#### 裏技① 「キャラ固定」は参照画像3枚で十分
Midjourney で `--cref` を駆使するより、NanoBananaに **同じキャラの正面・横顔・全身の3枚** を渡して「このキャラで」と指示する方が安定します。

#### 裏技② サムネは「先に文字、後に絵」
日本語タイポをまず確定させ、後から背景・人物を足す方が綺麗にいきます。逆順は文字が崩れがち。

#### 裏技③ 「ジブリ風」「鳥山明風」など作家名は **作風タグに変換**
作家名を直接書くと弾かれる/質が落ちる時は、その作家の特徴（線の太さ・配色・構図）を箇条書きで指定する方が安定します。

#### 裏技④ 「アスペクト比」は画像例で示せ
「16:9で」と書くより、**「以下の画像と同じ比率で」と参照画像を渡す**方が確実に通ります。

#### 裏技⑤ 「うまく出ない時は反対側から」
「美しい朝の海を」が出ないなら、「**何もない海岸線。日の出。空気の透明感**」のように構成要素分解で記述する。形容詞より名詞のスタック。

## ③ Google Flow × Gemini Omni — Veo 3.1並走の動画スタジオ

### 3-1. Flow と Omni の関係（30秒で）

ここは混同されがちなので最初に整理。

- **Google Flow** ＝ Google Labs の **動画制作スタジオ（UI/ツール）**。`labs.google/fx/flow` でアクセス。
- **Gemini Omni** ＝ Flow 内で選べる **動画生成モデル**（I/O 2026 で追加）。画像・音声・動画・テキストを混ぜて入力 → 高品質動画。
- **Veo 3.1** ＝ Flow に元々搭載されている動画モデル。時間的一貫性／同期音声／台詞／精密カメラコントロールに強い。

→ Flow という**ツール**の中に、Omni と Veo 3.1 という**2モデル**が並走している関係。用途で使い分けます。

**Gemini Omni の最大の差分は「会話型編集（conversational editing）」**。
一度作った動画に対し「主人公の服を赤に」「最後のカットだけ夕方に」と**継続指示が通り、キャラ・物理・前シーンの記憶が保たれる**のが革命的。
従来は1プロンプト1動画で作り直しだったのが、対話で詰められるようになった。

**Gemini Omni Flash** は無料枠が広く、YouTube Shorts / YouTube Create アプリにも展開済み（2026年5月時点）。

> **未確認**：Omni と Veo 3.1 の品質比較ベンチマーク、商用利用ライセンス詳細、Flow Music の日本提供状況。

撮影現場の使い分け：
- 動きの繊細さ・台詞リップシンク → **Veo 3.1**
- 会話で詰めたい / 既存画像を動かしたい → **Gemini Omni**
- ダンスや人物アクションのリアリズム → **SeeDance 2.0**（別系統・ByteDance）

### 3-2. 裏技ポイント 5選

#### 裏技① **Gemini Omni** には「**前カットの参照画像**」を必ず渡す
会話型編集の真価は「前を覚えてる」こと。最初のカットを画像/動画として参照に追加すると、続編生成の一貫性が桁違い。

#### 裏技② **Veo 3.1 のリップシンク** は「字幕指定」が安定
セリフを「彼が "おはよう" と言う」と書くより、**「字幕：おはよう」**として指示すると口の動きが綺麗。Omni 側も同じ流儀が通る。

#### 裏技③ 絵コンテ → Flow は **Gemini で「ショットリスト整形」を経由**
Flow に直接書かず、まず Gemini に **「Flow用ショットリスト形式」で絵コンテを書かせる** → コピペ。品質が一段安定。

#### 裏技④ Omni は **「画像を起点」** に始める方が成功率が高い
テキストonlyより、**先に NanoBanana で1枚絵を作る → それを Omni に動かしてもらう**方が、キャラ・構図のブレが出ない。

#### 裏技⑤ **失敗カットも資産化**
意図と違う生成結果も「変な世界観のB-roll」として後で刺さる。**「失敗フォルダ」を必ず作る**運用を徹底。SeeDance / Veo 失敗作も同様。

## ④ Stitch でUI設計 → Antigravity で開発

### 4-1. Stitch / Antigravity とは（30秒で）

- **Stitch** ：Google Labs の **テキスト → UI モックアップ** ツール（stitch.withgoogle.com）。「ToDoアプリのトップ画面を、明るいトーンで」のような自然言語で UI を生成し、Figma へのエクスポートやコードへの変換も可能
- **Antigravity** ：Google の **IDE型エージェント** （後発のエージェント型開発環境）。Cursor / Claude Code 系と比べ、Gemini のマルチモーダル性とコードベース全体把握を活かした「**指示すると複数ファイルを並行編集**」が特徴

このペアの強みは「**デザイン → 実装** の谷を埋める」こと。
Stitch で UI 仕様を視覚化 → そのスクリーンショットを Antigravity に渡して実装、というワークフローで、企画から動くプロトタイプまで数時間に短縮できます。

### 4-2. 裏技ポイント 5選

#### 裏技① Stitch には **「対象ユーザー」を最初に書く**
「ToDoアプリ」ではなく「**40代男性会社員向けの ToDo アプリ**」と書くと、配色・余白・フォントサイズが一気に大人びる。

#### 裏技② Antigravity に **Stitch のスクショを直接添付**
言葉で指示するより、UI画像を渡して「**この通りに**」と言う方が圧倒的に速い。Geminiのマルチモーダル性をフル活用。

#### 裏技③ 「制約条件」を最初に並べる
使うフレームワーク・依存ライブラリ・命名規則を **「制約」ブロックで明示** すると、Antigravityが既存コードベースに馴染む実装をしてくれる。

#### 裏技④ 「テストファースト」モードを使う
Antigravityに「**先にテストを書いて、それが通るように実装して**」と指示すると、品質が一段上がる（特に複雑なロジック）。

#### 裏技⑤ コミット粒度は **「機能単位」を明示**
「全部できたらコミットして」より「**この機能ができたら1回コミット、次の機能ができたらもう1回**」と指示する方が、後でレビューしやすい。

## ⑥ NotebookLM × Gemini 3.5 Flash 統合体（＋Gem / GAS / Workspace）

### 6-1. 「ただ使う」から「Gemini 3.5 Flash搭載で再生した」NotebookLM

NotebookLM は **「与えた資料の中だけで答える」リサーチAI**。
2024年の登場時は便利だが少し鈍重なツールでしたが、**2026年に入って一気に "頭脳" が変わりました**。

#### 何が起きたか
1. **Gemini 3.5 Flash 搭載**（I/O 2026 のタイミングで反映）
   - 4倍高速＝Audio Overview 生成・要約・質疑応答のレスポンスが体感倍速
   - 100万トークン入力＝**書籍3冊＋競合動画20本＋自社過去記事を全部突っ込んでもまだ余裕**
   - エージェント力＝「資料の中から仮説を組み立て、根拠付きで提示」が破綻しない
2. **Gemini連携の強化**（2026年4月）
   - Gemini chat の `+` ボタンから NotebookLM のノートをソースとして呼び出し可能
   - 「**統合ではなく相互参照**」というGoogleの設計判断
3. **ビジュアル化**（2026年3月）
   - フローチャート／階層図／タイムライン／比較チャートなど **10種類のビジュアル形式**でアウトプット可能
4. **学生向け Google AI Pro 無料化** → NotebookLM が広く使える前提に

> **未確認**：Audio Overview の日本語ホスト音声の選択肢、Gemini chat ↔ NotebookLM の同期遅延。

#### つまり何が変わったか
従来：「リサーチ補助の便利ツール」
2026以降：「**Gemini本体と地続きの "外部側頭葉"。資料を投げ込み、自然言語で問い、必要な瞬間にGemini Chatや Gem や GAS へ素材として流す**」

→ **「NotebookLM 単体」ではなく、Gem・GAS・Workspace と組んで業務OSを作る**のが2026年型の使い方です。

### 6-2. 裏技ポイント 5選（NotebookLM単体）

#### 裏技① 「**ノートブック1つ＝1テーマ**」に絞る

### 6-3. Gem — 自分専用Geminiを量産する

**Gem** は Gemini Advanced 内で **役割・指示・参照資料を永続化したカスタムGemini**。
「@編集者」「@ファクトチェッカー」のように呼び出すイメージ。

#### 撮影業務で必ず作るべきGem 3体
1. **ファクトチェッカーGem** — 公開前の最終ゲート（誇張・出典なし数値・固有名詞ミスを潰す）
2. **タイトル屋Gem** — 既知の自分のヒット傾向を参照し、複数案を即出し
3. **要約Gem** — 長文資料を「自分の文体で」3行に圧縮

#### Workspace連携の決定打
Gem に対し **Workspace内のコンテンツ参照を許可** すると、Gmail / Calendar / Docs / Drive / Keep / Tasks を横断して答えを返せます。
例：「来週の会議について、関連メール＋カレンダー＋直近Docsを参照してアジェンダ案を作って」が1プロンプトで通る。

### 6-4. GAS（Google Apps Script）× Gemini — 業務自動化の核

2026年1月、**Apps Script に Vertex AI Service が Advanced Service として追加**。
これにより：
- **API キー不要**で Gemini API を呼べる（Workspace 認証で完結）

- 2026年6月から Apps Script が **Workspace Core Service** に昇格 → SLA・セキュリティが本番品質に

#### 撮影ワークフローでの典型用途
1. スプレッドシートで動画ネタ管理 → 関数で「フックを5案生成」
2. Gmail に届く視聴者問い合わせを自動分類・自動返信下書き
3. Calendar の予定から週次レポートを生成して Slack に流す

### 6-5. Google Workspace 内 Gemini — Docs / Sheets / Gmail で発火させる

Gemini は Workspace 各アプリのサイドパネル／ショートカットで呼べます。撮影業務で刺さる即実用ハック：

- **Docs** → 「Help me write」で台本下書き、選択範囲を「Rephrase」で文体統一

- **Gmail** → 「Summarize this thread」で長いスレッドを3行に、「Help me write」で返信下書き
- **Calendar** → 自然言語で「次の月曜15時に〇〇さんと30分」→ 自動で空き照合・招待
- **Drive** → ファイル横断で「この案件のすべての資料」を検索

→ これら全てが Gemini 3.5 Flash 基盤になり、応答速度と精度が一段上がった。

```javascript
// Apps Script に貼る（Vertex AI Service 有効化済み前提）
// Sheets 上で =GEMINI("3行で要約して", A1) のように呼べる

function GEMINI(instruction, ...inputs) {
  const text = inputs.flat().filter(Boolean).join("\n");
  const project = "{あなたのGCPプロジェクトID}";
  const location = "us-central1";
  const model = "gemini-3.5-flash";

  const url = `https://${location}-aiplatform.googleapis.com/v1/projects/${project}/locations/${location}/publishers/google/models/${model}:generateContent`;

  const payload = {
    contents: [{ role: "user", parts: [{ text: `${instruction}\n\n# 入力\n${text}` }] }],
    generationConfig: { temperature: 0.3, maxOutputTokens: 1024 }
  };

  const res = UrlFetchApp.fetch(url, {
    method: "post",
    contentType: "application/json",
    headers: { Authorization: "Bearer " + ScriptApp.getOAuthToken() },
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  });

  const json = JSON.parse(res.getContentText());
  return json?.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
}
```

// 受信トレイの未読メールを Gemini で分類し、ラベル付け＋下書き返信を作成
function triageInbox() {
  const threads = GmailApp.search("is:unread label:inbox", 0, 20);
  threads.forEach(t => {
    const msg = t.getMessages().pop();
    const body = msg.getPlainBody().slice(0, 4000);

    const cls = GEMINI(
      "次のメールを {依頼/苦情/質問/営業/その他} のいずれかに分類し、JSON {category, urgency:1-5, reply_draft}で返して。",
      body
    );
    const parsed = JSON.parse(cls);

    const label = GmailApp.getUserLabelByName(parsed.category) || GmailApp.createLabel(parsed.category);
    t.addLabel(label);

    if (parsed.urgency >= 4) {
      msg.createDraftReply(parsed.reply_draft);
    }
  });
}

### 7-2. 連携の3原則

1. **「入力→出力」をテキスト/画像で繋ぐ**：APIなしでも、コピー＆ペーストで十分連携できる
2. **「人が判断する箇所」を明確化**：AIに任せていい所と、判断を人が握る所を分ける
3. **「失敗パターン」を memory に書き溜める**：同じ詰まり方を2度しないために、必ずメモ化

### 7-3. 「やってはいけない」連携

- 全部AI任せで公開（必ずファクトチェック工程を入れる）
- 1ツールに全タスクを集約（用途別の強みを潰す）
- 出力を保存せず使い捨て（再現性が消える）

## ⑧ 付録：プロンプト改造の3原則

本資料の全プロンプトは、以下3原則で改造すると質が劇的に上がります。

### 原則① 「役割」を最初に1行で固定する

❌ 「〇〇について教えて」
⭕ 「**あなたは{役割}です。以下の前提で{役割}として答えてください**」

役割を与えるだけで、出力の語彙・視点・優先順位が変わります。

### 原則② 「出力フォーマット」を末尾で縛る

❌ 「箇条書きでお願い」（曖昧）
⭕ 「**以下のJSON形式で出してください。{ "title": "", "body": "", "tags": [] }**」

フォーマットを構造化すると、後段ツールへの流し込みが楽になります。

### 原則③ 「NG」を明示する

❌ NGを書かない
⭕ 「**以下は禁止：誇張表現／出典なき数値／曖昧な「らしい」**」

NGを明示すると、ハルシネーション系の事故が激減します。
