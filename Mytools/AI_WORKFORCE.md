# Mytools AI Workforce

`Mytools` 用の AI 社員設計です。

共通テンプレートは `../AIWorkforceTemplate/` を参照します。このファイルでは、PDF 結合ツールなどの小さな Windows ツールを改善、検証、記録するための役割だけを切り出して使います。

## 目的

- ツール改善を、要件、調査、実装計画、修正、テスト、説明、記録に分ける
- 既存の `.bat`、`.py`、`README.md` の構成を保ちながら安全に変更する
- 生成物や一時ファイルを GitHub に含めない判断を残す
- 初心者にも再実行できる確認手順を残す

## Mytools の AI 社員

| 順番 | AI 社員 | 元の汎用役割 | 担当 |
| --- | --- | --- | --- |
| 1 | ツール要件整理担当 | `@requirements-architect` | 直したい不便、対象ファイル、完成条件を整理 |
| 2 | 既存コード調査担当 | `@researcher` | `.bat`、`.py`、README、設定ファイルの現状確認 |
| 3 | 改善手順設計担当 | `@planner` | 変更手順、影響範囲、テスト観点を分解 |
| 4 | ツール実装担当 | `@creator` | Python、バッチ、README、設定を修正 |
| 5 | 動作確認担当 | `@reviewer` | エラー、回帰、Windows 固有の問題、依存関係を確認 |
| 6 | README・手順整形担当 | `@formatter` | 使い方、インストール、exe 化手順を整える |
| 7 | 変更記録係 | `@archivist` | 変更内容、未解決事項、次回改善案を保存 |

## 標準フロー

```text
ツール要件整理担当
  -> 既存コード調査担当
  -> 改善手順設計担当
  -> ツール実装担当
  -> 動作確認担当
  -> README・手順整形担当
  -> 変更記録係
```

小さい修正では、`既存コード調査担当 -> ツール実装担当 -> 動作確認担当` だけで進めます。

## 入力

- 直したい動作、不具合、追加したい機能
- 実行時のエラーメッセージ
- 既存の `.bat`、`.py`、`README.md`
- 期待する出力ファイルや操作手順

## 出力

- 要件メモ
- 変更計画
- 修正済みコード
- 動作確認メモ
- README 更新案
- 引き継ぎメモ

## 保存方針

推奨保存先:

```text
Mytools/
  tool-projects/
    [tool-change-name]/
      requirements.md
      plan.md
      test.md
      handoff.md
```

既存の README やスクリプトに直接反映できる小さな変更では、別フォルダを作らず対象ファイルだけを更新します。

## 人間に確認するポイント

- 何を便利にしたいか
- 既存動作を変えてよいか
- 生成した `.exe` や PDF を GitHub に含めないか
- テストに実ファイルや個人ファイルを使ってよいか

## 禁止事項

- ユーザーの実ファイルを勝手に削除、移動、上書きしない
- `.exe`、出力 PDF、一時ファイルを理由なく GitHub に含めない
- Windows 専用依存を増やす場合に README へ書き忘れない
- テストしていない変更を「確認済み」と言わない
