# Task: ローカルCodex起動案内の改善と反省点

## 目的

`Start-Codex-GPT-OSS-20B` と「作業場所判定ランチャー」からローカルCodexを起動したとき、参考資料の有無や種類に応じた操作方法を、入力欄の直前に分かりやすく表示する。

## 最終的な仕様

- 参考資料が無い場合は、そのまま依頼を入力して開始する。
- 参考資料が文章の場合は、`Ctrl+V` で本文を貼り付け、その下に依頼を書く。
- PDFなどのファイルの場合は、ファイル自体を貼り付けず、フルパスと依頼を書く。
- Codexに「準備できました」と返答させる事前メッセージは送らない。
- 案内はCodexの入力欄が現れる直前に日本語で表示し、画面から消えにくくする。
- 起動時に生成する `Codex-Reference-Pack.md` は補助資料とし、必要な範囲だけ参照する。

## 度重なる修正が必要になった理由

### 1. 利用者向け案内とCodex向け指示を混同した

「この案内を表示したまま、『準備できました』とだけ返答してください」という文章は、誰が誰に指示しているのか分かりにくかった。さらに、Codexが不要な準備処理を開始し、利用者が本来の依頼を入力するまでに一往復増えた。

### 2. 参考資料がある前提の案内になった

最初の案内では、参考資料を使わない通常の利用方法が明示されていなかった。「参考資料が無い場合」を最初に書かないと、毎回資料を用意する必要があるように見える。

### 3. 文章とファイルの渡し方を区別できていなかった

`Ctrl+V` で渡せるのは主にクリップボード上の文章である。PDFなどはファイル自体の貼り付けを前提にせず、Codexから読めるフルパスを依頼文に書く必要がある。

### 4. 正しい案内でも表示タイミングが早すぎた

重要な案内を起動処理の途中に表示すると、後続のログやCodexの画面切り替えによって消える。文章の正しさだけでなく、「入力欄が出る直前」「読み返せる状態」という表示上の受け入れ条件が必要だった。

### 5. CMDとPowerShellの境界を十分に検証しなかった

文字コード、引用符、改行、空の `-File` 引数などが崩れると、文章の一部がコマンドとして解釈される。今回の `'PER'`、`'exist'`、`-File ''`、文字化けなどは、複数のシェルをまたぐ処理を断片的に確認したことが原因だった。

### 6. 実際の起動全体より個別部分の確認を優先した

PowerShellの構文や案内文だけが正しくても、ランチャーからLM Studio、Codexの入力欄までの流れが正しいとは限らない。意図しない巨大モデルのダウンロードが始まる可能性も含め、実行前の安全確認が不足していた。

## 採用した改善

- Codexへの自動準備メッセージと「準備できました」の往復を廃止した。
- 案内を「資料なし」「文章」「PDFなどのファイル」の順にした。
- `Clear-Host` で直前の冗長な表示を整理してから、最終案内を表示するようにした。
- Codexを `--no-alt-screen` で起動し、直前の案内が端末に残りやすい構成にした。
- 警告記号や重複案内を減らし、入力例には実際のリポジトリ配下のパスを使った。
- 参考資料パックは自動生成物として扱い、Gitの管理対象から外した。

## 検証結果と残る注意点

- 関連PowerShellスクリプトは構文解析を通過した。
- `git diff --check` では改行コードの警告以外に問題はなかった。
- 実モデルを使う完全な自動起動試験は、大容量モデルのロードやダウンロードを伴うため実施していない。
- 最終的な画面上の残り方は、利用者による実起動で確認する必要がある。

## 今後の判断基準

ランチャーの親切設計は、説明を増やすことではない。通常利用を妨げず、必要な人が必要な瞬間に、迷わず次の一手を選べることを基準にする。
