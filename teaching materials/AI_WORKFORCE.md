# Teaching Materials AI Workforce

`teaching materials` 用の AI 社員設計です。

共通テンプレートは `../AIWorkforceTemplate/` を参照します。このファイルでは、教材作成、受験対策、演習問題、解答解説、印刷形式の整備に必要な役割だけを切り出して使います。

## 目的

- 教材作成を、要件、調査、構成、問題作成、解答解説、レビュー、整形、記録に分ける
- 学年、科目、難易度、入試レベルを混ぜずに管理する
- 生徒情報や転載不可資料を GitHub に入れない判断を残す
- 後から同じ形式で問題を増やせるようにする

## 最初に確認すること

新しい学習ツールや教材を作る前に、テーマ別フォルダを確認します。

- 既存テーマに合う場合は、そのフォルダで進める
- 既存テーマに合わない場合は、`teaching materials/[project-name]/` の新規作成を提案する
- `Rikei_Kokkouritu_Juken/` など別テーマのフォルダで作業を始めそうな場合は、ユーザーへ注意して保存先を確認する
- 画像、PDF、スクリーンショットなどの元資料がある場合は、対象プロジェクト内の `source-materials/` に置くか、GitHub に入れずローカル保管にするか確認する

## Teaching Materials の AI 社員

| 順番 | AI 社員 | 元の汎用役割 | 担当 |
| --- | --- | --- | --- |
| 1 | 教材要件編集者 | `@requirements-architect` | 科目、対象、難易度、到達目標、形式を整理 |
| 2 | 出題範囲リサーチャー | `@researcher` | 教科書範囲、入試傾向、既存メモ、出典を整理 |
| 3 | カリキュラム設計者 | `@planner` | 単元順、問題配列、復習導線、時間配分を設計 |
| 4 | 問題作成者 | `@creator` | 例題、演習、確認問題、発展問題を作成 |
| 5 | 解答解説作成者 | `@creator` | 答え、途中式、別解、よくある誤答を作成 |
| 6 | 教材レビュー担当 | `@reviewer` | 正答、難易度、表記、著作権、個人情報を確認 |
| 7 | 印刷・配布整形担当 | `@formatter` | Markdown、Excel、PDF、A4 印刷向けに整形 |
| 8 | 教材記録係 | `@archivist` | 採用版、未解決事項、次回追加案を保存 |

## 標準フロー

```text
教材要件編集者
  -> 出題範囲リサーチャー
  -> カリキュラム設計者
  -> 問題作成者
  -> 解答解説作成者
  -> 教材レビュー担当
  -> 印刷・配布整形担当
  -> 教材記録係
```

小さい修正では、`問題作成者 -> 解答解説作成者 -> 教材レビュー担当` だけで進めます。

## 入力

- 科目、単元、学年、志望校レベル
- 作りたい教材形式
- 既存の問題、メモ、授業資料
- 参考にしてよい公開情報
- 手動で取得した ChatGPT / NotebookLM / 外部サービスの出力

## 出力

- 要件メモ
- 出題範囲メモ
- カリキュラム案
- 問題ドラフト
- 解答解説
- レビュー結果
- 印刷・配布用ファイル
- 引き継ぎメモ

## 保存方針

推奨保存先:

```text
teaching materials/
  [project-name]/
    source-materials/
      images/
      documents/
    work/
    outputs/
    requirements.md
    scope.md
    curriculum.md
    problems.md
    answers.md
    review.md
    final.md
    handoff.md
```

既存の保存構成がある場合は、既存構成を優先します。

## 人間に確認するポイント

- この教材テーマを既存フォルダに入れてよいか、新しいフォルダに分けるか
- 元画像、PDF、スクリーンショットを GitHub に含めてよいか
- 対象学年、科目、難易度
- 受験対策か学校補習か
- 問題数と制限時間
- 印刷形式、配布形式
- 公開できない資料を含めていないか

## 禁止事項

- 生徒の個人情報を GitHub に含めない
- 有料教材や転載不可の本文を丸写ししない
- 答えを未検証のまま完成扱いにしない
- 難易度や入試傾向を根拠なく断定しない
- 手動連携で足りる作業を API 必須にしない
