# 競合リサーチ SOP（自分のジャンルで勝ち記事を集める手順）

運用するジャンルの「人気アカウント・勝ち記事・構成・有料ラインの引き方」を、
researcher が自分で集めて `note-team/ナレッジ/競合リサーチ_<ジャンル>.md` にまとめるための手順。

> このキットには特定ジャンルの競合データは同梱していません。**必ず自分のジャンルで実データを取る**こと。
> 競合記事は**構成・型の分析のみ**に使い、文章のコピーはしない（著作権）。

---
## 方法1：noteの公開JSON APIを使う（速くて確実・推奨）

noteはJSレンダリングが重く、検索/一覧の単純なHTML取得は不安定。
**ブラウザでnote.comのタブを開いた状態**で、そのページ内から同一オリジンの `fetch` を実行すると公開APIが素直に返る。
（Claude Code の Chrome拡張＝ブラウザ操作ツールがあれば、note.comのタブ上で `fetch().then(r=>r.json())` を実行できる。
拡張が無い場合は「方法2」へ。）

主要エンドポイント（いずれも `credentials:'include'` 推奨、`?` パラメータは適宜変更）：

- **検索**：`GET /api/v3/searches?context=note&q=<キーワード>&size=30&start=0&sort=popular`
  → `data.notes.contents[]`（key, name, price, type, user.urlname, user.nickname）
  ※検索APIは **スキ数(likeCount)を返さない**ので、人気判定はフォロワー数や記事APIで取り直す。

- **クリエイター情報**：`GET /api/v2/creators/<urlname>`
  → `data`（nickname, followerCount, noteCount, profile=自己紹介）。人気ランクは followerCount で取るのが確実。

- **クリエイターの記事一覧**：`GET /api/v2/creators/<urlname>/contents?kind=note&page=1`
  → `data.contents[]`（key, name, likeCount, price）。ここは likeCount が入るのでスキ数で人気記事を特定できる。

- **記事本文**：`GET /api/v3/notes/<key>`
  → `data`（name, price, body=HTML, canRead）。有料記事は無料プレビュー部分の body のみ返る。
  見出し構造は `body.match(/<h[1-4][^>]*>(.*?)<\/h[1-4]>/g)`、本文文字数は `replace(/<[^>]+>/g,'')` でカウント。

実行のコツ：
- async IIFE で複数fetchを直列/並列にまとめ、1回で必要フィールドだけ返すと往復が減る。
- 出力は `title.slice(0,40)` などで短縮し、巨大化・途中切れを防ぐ。
- **除外すべきノイズ**：相互フォロー目的アカウント（プロフに「フォロバ100%」等）、ジャンル無関係の著名人。followerCount上位でも内容で弾く。

## 方法2：手作業で集める（拡張が無い場合）

1. note.com でジャンルの主要キーワードを「人気」順で検索。
2. 上位に繰り返し出てくる著者を10名ほどリストアップ（フォロワー数・更新頻度を見る）。
3. 各著者の人気記事（スキの多い順）を3〜5本開き、次を記録：
   - タイトルの型（数字／対比／当事者／記号／縦棒タグ）
   - 無料記事の構成（フック→本編→CTAの流れ、見出しの付け方）
   - 有料記事の「無料パートで何を見せ、どこで有料に切るか」
   - メンバーシップの有無・価格・特典
4. 共通項を「型」として抽象化し、`勝ちパターン_フレームワーク.md` のA〜Fに当てはめて追記。

---
## まとめ方（成果物フォーマット）
`note-team/ナレッジ/競合リサーチ_<ジャンル>.md` に：
1. 調査日・ジャンル・対象キーワード
2. 人気アカウント一覧（ニックネーム・フォロワー数・扱うテーマ・代表記事）
3. テーマの型／タイトルの型／無料構成／有料ライン／メンバー設計の共通パターン
4. 自チームが取るべき差別化ポジション
5. 出典（URLは記録するが、本文の引用・転載はしない）

定点観測：月1回ほど更新し、勝ち記事の入れ替わりを追う。
