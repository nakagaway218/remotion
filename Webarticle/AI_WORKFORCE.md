# Webarticle AI Workforce

`Webarticle` 用の AI 社員設計です。

共通テンプレートは `../AIWorkforceTemplate/` を参照します。このファイルでは、Web 記事制作に必要な役割だけを切り出して使います。

## 目的

- 記事作成の工程を、調査、構成、本文、レビュー、整形、記録に分ける
- ChatGPT Plus などの手動連携を前提にしつつ、AIで中間成果物を残す
- NotebookLM や外部リサーチは任意にし、必須化しない
- 出典、未確認事項、次回引き継ぎを残して再開しやすくする

## Webarticle の AI 社員

| 順番 | AI 社員 | 元の汎用役割 | 担当 |
| --- | --- | --- | --- |
| 1 | 記事要件編集者 | `@requirements-architect` | キーワード、読者、記事目的、成果物形式を整理 |
| 2 | 記事リサーチャー | `@researcher` | 既存資料、検索メモ、参照元、競合記事の材料整理 |
| 3 | 記事構成ディレクター | `@planner` | タイトル、見出し、本文前チェック、読者導線を設計 |
| 4 | 記事ライター | `@creator` | 本文、導入、まとめ、FAQ、メタ説明文を作成 |
| 5 | ファクト・品質レビュー担当 | `@reviewer` | 根拠、矛盾、タイトル回収、SEO過剰表現、法務リスクを確認 |
| 6 | 入稿整形担当 | `@formatter` | Markdown、WordPress向けHTML、Google Docs向け構成に整形 |
| 7 | 記事記録係 | `@archivist` | 採用案、未解決事項、出典、次回引き継ぎを保存 |

## 標準フロー

```text
記事要件編集者
  -> 記事リサーチャー
  -> 記事構成ディレクター
  -> 記事ライター
  -> ファクト・品質レビュー担当
  -> 入稿整形担当
  -> 記事記録係
```

小さな修正では全員を使わず、`記事ライター -> ファクト・品質レビュー担当 -> 入稿整形担当` だけで進めます。

## 入力

- キーワード、テーマ、想定読者
- 既存の記事案、メモ、調査結果
- 手動で取得した ChatGPT / NotebookLM / 外部サービスの出力
- 参照すべき URL や資料

## 出力

- 要件メモ
- リサーチメモ
- 構成案
- 本文ドラフト
- レビュー結果
- 入稿用本文
- 引き継ぎメモ

## 保存方針

推奨保存先:

```text
Webarticle/
  projects/
    [article-name]/
      requirements.md
      research.md
      outline.md
      draft.md
      review.md
      final.md
      handoff.md
```

既存の保存構成がある場合は、既存構成を優先します。

## 人間に確認するポイント

- 記事目的と読者が合っているか
- タイトルと見出しの方向性
- 本文前の構成採用
- 出典が弱い主張を残すか削るか
- 最終公開前の表現

## 禁止事項

- 根拠がない数値を断定しない
- 外部出力を未検証のまま事実として扱わない
- 案件固有の秘密情報や個人情報を GitHub に含めない
- NotebookLM や API 利用を標準必須にしない
